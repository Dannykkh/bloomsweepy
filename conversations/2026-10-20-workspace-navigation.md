# 작업 중심 메뉴·설정 UI 개편

## 사용자 요청 — 기록 22:56 KST

2026-10-20. 원래 사용자 턴 시각은 제공되지 않았다.

사용자: “지금 전체적으로 많이 부족해보이는데? 메뉴구성이나 ui구성은 다 다시 맞게 한거야?”
이후 사용자: “진행해”.

전체 메뉴와 화면 연결 감사에서 확인한 문제를 구현 대상으로 삼았다. 기존 Swift 계열 글래스, Rust 기반 기능, 승인·삭제 엔진을 보존하고 메뉴 그룹/현재 위치, 설정 분류, 대시보드 밀도와 시스템 정리 진입을 정비했다. 설치·커밋·푸시는 이번 요청에 포함하지 않았다.

## 실제 검증과 결정

그레이스케일 구조 렌더 후 기능별 병렬 구현. 세 시각후보의 데스크톱/좁은 화면을 비교하여 기존 제품 방향과 일치하는 A dark-glass를 자동 선택했다. 새 사용자 선택을 받은 것으로 기록하지 않는다. 실제 앱 컴포넌트를 fail-closed IPC 합성 환경에서 검사했다. 설정500MB 값 유지, 모델 조회1회, 메뉴 조건/현재 위치, 다중 드라이브, 시스템 후보 직접 진입을 확인했다. 390px 헤더 잘림은 상속 flex-wrap/percentage basis를 바로잡아 해소했다.

타입 검사·배포 빌드·frontend154개 테스트 통과. Windows UI 조건은 합성 검증이며 Windows 실행/설치된 앱 교체/네이티브 글래스 재검증은 하지 않았다. 상세 근거: [UI QA](../docs/qa/workspace-navigation/verify-report.md), [새 결정017](../memory/architecture/017-workspace-navigation.md).
