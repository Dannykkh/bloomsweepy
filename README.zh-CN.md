BroomSweepy 是一个面向 Windows 和 macOS 的**对话式文件管理系统**开发项目。项目以对话为主要操作方式，目标是让文件搜索、扫描、候选项审核、条件调整、最终确认和结果查看在同一工作流程中连续完成。

**当前开发和构建统一使用 Rust + Tauri 2 + React**，延续了原 SwiftUI 应用宽敞的卡片、清晰的图标和玻璃质感界面。旧版 Swift 源码和 Xcode 项目不再包含在当前工作树或构建目标中。大文件分析、经过验证的重复文件和文档搜索由本地 Rust 引擎处理；现有的浏览与扫描界面无需连接 AI 也可使用。一个安装版本支持英语、韩语、日语和简体中文，首次启动默认英语，可在 `Settings > Display language` 中更改。

## v1.8.0 — 对话式文件与文件夹管理

内置聊天的回收站移动默认通过一次**是/否**确认，不再要求另开审核弹窗，也不会仅因等待时间而使确认过期。在输入框的**权限选择**或**设置 → AI 与权限 → 连接与权限 → 聊天权限**中选择`只读`、`确认后执行`（默认）或`完全访问`（`full_access`）。只读模式不准备或执行变更。显式选择完全访问后，像“删除 promo-video”这样明确列出所有目标名称的简单、直接文件/文件夹/应用本体删除请求，经重新验证后可直接处理。条件句、咨询、引用、复合句或不支持的表达仍需是/否确认。“可以删除吗？”、目标不明、相关数据、进程退出、Docker 清理和永久删除不在自动授权范围内。权限偏好遵循现有保留方式，但单项计划和批准不保存，也没有新增 MCP 或模型的执行工具。[确认流程 QA](docs/qa/2026-10-05-conversational-trash-consent.md)

完全访问模式下，打开文件夹对话后可通过**本地驱动器列表**或聊天请求查询本地卷，并将全盘名称搜索结果中的准确目标交给现有文件管理卡片。搜索有时间、项目数量和内存上限，不跟随云端、网络位置或其他挂载点。无法读取或达到限制的结果会标为部分结果，不用于自动移入回收站。此模式不授予 macOS“完全磁盘访问权限”、文档正文授权、外部 MCP 权限或永久删除权限，也不会把旧的跳过确认设置自动迁移为完全访问。[权限模式验证](docs/qa/2026-10-11-chat-access.md)

**清理候选 → 文件夹树**可展开子文件夹，进行全选或单项选择。选择父项会包含其子项；取消某个子项后，不会移动父文件夹本身。可从容量地图或AI的已测量列表打开同一扫描结果，最终确认后移入回收站。此新页面会严格检查隐藏的受保护项目、链接、云目录及设备边界。状态最多2,048个节点，界面最多200行，并明确显示未测量、部分结果和过期状态。2026-10-05 显示版本为 1.7.0 的 Mac 开发版已验证3个临时目标共209B移入回收站、子文件保留、取消、重新扫描、AI本地卡片入口及重启后的历史记录。Windows、外部模型调查全流程及长时间内存测试仍未完成。[文件夹树验证记录](docs/qa/2026-10-05-cleanup-tree.md) · [Mac实机验证](docs/qa/2026-10-05-cleanup-tree-native.md)

询问“这里最大的文件夹或数据是什么？可以删除吗？”会重新测量当前文件夹的直属项目并按容量排序。文件夹容量包含其下属项目，仅凭容量不能判断删除是否安全。点击**在容量地图查看相同结果**可在树状图复用同一次扫描。仅按名称找到的文件夹，在检查其内容前仍为未测量状态。部分结果、读取失败和过期快照会区分显示；仅提出这个问题不会选择删除目标或删除任何内容。

向 AI 请求扫描、按名称查找或清理 `promo-video` 等文件夹，Rust 应用会实际执行搜索、容量扫描、子文件夹浏览和回收站移动审核，也支持非空文件夹。同一对话的卡片提供打开、显示位置、调整选择、最终确认及逐项结果。模型只能请求应用操作，不能获得删除权限。

名称搜索最多保留200项，AI和界面每页24项，一次移动审核最多100项。未扫描的文件夹大小显示为未测量而非零。同名项目或不完整搜索不会自动选择目标。会显示完整路径、包含项目和逻辑大小，并在默认的是/否确认中说明文件夹及其全部子项将一起移动。聊天计划没有等待时间限制、仅可使用一次，修改选择、重新扫描或重启会使其失效。执行前重新检查变更、链接、云目录及受保护路径。不提供永久删除、任意 Shell、对话重命名、普通移动或创建文件夹。

这些新增功能包含在 v1.8.0 对应源码中，现有 GitHub v1.7.0 下载不包含。实际 Codex 扫描/非空文件夹审核请求及合成项目的 macOS 回收站移动，是显示版本为 1.7.0 的开发版验证历史。Windows 实机及长时间资源验证仍未完成。

在macOS中，真实文件夹内的`node_modules/.bin`等符号链接只移动链接本身，不遍历目标。审核卡片显示单独的链接数量，执行前检测目标变化。仍保护所选项/父路径中的链接、云目录、跨设备边界和特殊项；Windows重解析点/目录联接仍被拒绝。[开发版验证记录](docs/qa/2026-10-04-conversational-files.md)

### 任务导向菜单与应用设置

菜单分为**计算机**（仪表板 → 性能 → 应用管理 → 对应系统的 Mac 设置/Windows 设置）、**文件与空间**（空间清理 → 文件查找）和**工具**（AI 助手 → 可选 Docker 管理），设置位于底部。不显示其他操作系统的设置菜单；进入子页面后仍以其上级菜单标示当前位置。Docker 管理默认关闭。

**应用设置**分为常规 / 扫描与搜索 / AI 与权限 / 文件监控 / 开发者工具 / 关于六类。切换分类不会重置设置或进行中的状态。仪表板紧凑展示实际驱动器名称、容量、扫描与快捷操作，其清理候选入口直接连接系统缓存/临时文件列表。Mac 设置不再放置重复的菜单快捷卡片，优先呈现设置操作与更改记录；文件夹树仍独立保留。[菜单与设置验证](docs/qa/workspace-navigation/verify-report.md)

**系统候选**的嵌套布局已改为全宽单列，初始扫描入口只保留一个。部分结果警告在摘要、筛选和选择区域之前显示，并修正了对应系统的说明、筛选项及长路径换行。开发缓存的重新构建/下载警告、审核确认、最终确认和执行前重新验证保持不变。这是模拟界面 QA，不代表实际删除或 Windows 原生运行已验证。[修正与验证范围](docs/qa/system-candidates-2026-10-21/review.md)

### macOS — Mac 设置与开发缓存

在 macOS 的`Mac 设置`中可查询文件扩展名、隐藏文件、路径栏、状态栏和文件夹优先排序五项设置。在`文件显示`、`路径与信息`两个分组中，先用`关闭`/`开启`选择草稿值，再点击旁边的`应用`保存。仅选择不会更改设置；未设置时两侧都不选中。通过顶部`设置更改记录`可`恢复原来的设置`，包括恢复为原本没有用户设置的状态。当前值与应用先前写入的值不一致时会拒绝恢复，但这不能原子性阻止其他程序同时修改。未设置不等于关闭，确认已保存也不代表 Finder 界面已反映更改；应用不会自动重启 Finder。

## v1.7.0 — 对话式工具与资源保护

以下功能范围及未验证项描述的是公开v1.7.0当时的状态。当前开发版的新增功能及验证见上文。

[正式发布与下载](https://github.com/Dannykkh/bloomsweepy/releases/tag/v1.7.0) · [更新日志](CHANGELOG.md)

- **对话式空文件夹清理**：连接本地重新扫描、候选卡片、对话排除、最终确认和逐项结果。
- **文件夹操作与打开文件**：从空间地图单独审核整个文件夹的回收站移动，区分“打开”与“显示位置”。
- **应用管理**：按名称、发布者和路径进行包含词搜索。Mac 的应用本体和相关数据分别审核；Windows 打开系统卸载页面。
- **清空系统回收站**：针对当前用户整个回收站的永久删除，需要单独确认，AI 无权调用。
- **资源保护**：有上限的流式遍历、索引内存与磁盘预算，以及独立文档处理进程。
- **macOS 菜单栏**：原生面板每10秒显示 RAM、CPU 和系统磁盘。保存内存数字显示设置；关闭窗口会隐藏，打开会恢复，退出/⌘Q 会完全结束应用。不创建额外 WebView。

菜单顺序为 **仪表板 → 性能 → 应用管理 → 空间清理 → 文件管理 → AI 助手 → 设置**。Docker 管理默认关闭。

### 对话式空文件夹清理流程

1. 在 AI 助手中选择本地文件夹，请求扫描空文件夹。
2. 审核重新扫描后的候选卡片，通过对话或复选框排除要保留的文件夹。
3. 核对准确路径和选择，点击**最终确认按钮**移入回收站。
4. 查看逐项成功、失败和跳过结果。

最多审核200项，每页向 AI 提供最多24项，并显示保护规则、变更或上限导致的遗漏数量。计划仅可使用一次，有效期五分钟，修改选择、重新扫描或重启会使其失效。聊天消息或 AI 回复本身不能授权执行。暂不支持通过对话移动普通文件或重命名。**新工具流程与实际 Codex CLI 的端到端验证仍未完成。**

### 应用管理与打开文件

`应用管理`无需扫描整个驱动器即可查看列表。Mac 优先使用应用的专用卸载程序，普通应用本体须单独确认后移入回收站。相关数据仅限通过准确应用标识符匹配的缓存和偏好设置，另行选择和审核。文档、Application Support、Containers 和共享数据不纳入自动候选项。Windows 打开系统正式的“已安装的应用”卸载页面，不推测删除应用文件夹、注册表或 AppData。打开页面不代表卸载完成。

“打开”会使用默认应用打开普通文档或媒体，使用文件管理器打开普通文件夹。可执行文件、脚本和应用包仅显示位置，不会执行。显示位置与应用内的子文件夹浏览是不同操作。这些功能不会扩大 AI、CLI 或 MCP 的删除权限。

### 本地处理、令牌与传输范围

文件搜索、扫描、汇总和候选项管理在本机完成，仅向 AI 提供有限摘要。本地文件操作本身不消耗 LLM 令牌。潜在节省来自发送必要摘要而非完整文件列表，并不是 Rust 语言本身的优势。设计良好的普通 CLI 也可能达到类似效率；尚未测量完成相同任务时的令牌节省比例。

云端 AI 会收到名称、大小、数量、候选项编号、问题和对话历史。应用生成的文件夹摘要和新候选项页面不会自动包含文件正文或完整路径，但用户输入的路径或内容可能进入问题和历史。本地 CLI 或只读权限不等于完全离线，也不保证阻止所有外部传输。另行授权的 MCP 文件和文档搜索可能返回路径与匹配片段，因此不承诺零数据传输或固定的令牌节省比例。

### 资源边界与验证限制

主进程内存超过512 MiB或系统可用 RAM 低于256 MiB时，协作式中断重任务。PDF、Office 工作进程采用128 MiB Rust 分配预算和15秒限制；索引失败保留上次完成的索引。这不是整个应用、WebView、CLI 的操作系统硬配额，也不保证解决内存泄漏。隐藏窗口仍保留原有状态与内存。

- 本地自动检查：273项 Rust 与43项前端测试通过，跳过1项可选实际 CLI 诊断。

## 安全与云端排除

扫描不会修改文件。大文件及重复检查、驱动器汇总、树状图、文件目录和文档索引会排除已知云同步根目录与仅在线项目。macOS 的 `~/Library/CloudStorage`、`~/Library/Mobile Documents` 以及可识别的 Google Drive、iCloud、OneDrive、Dropbox 路径在遍历前就会被排除，直接选择也不会扫描。已下载但位于识别出的云目录内的文件同样排除。无法保证识别任意迁移位置的同步文件夹或所有提供商。

重复文件依次通过大小、部分及完整 BLAKE3、最终字节比较验证。文件移动须经选择、重新验证、最终确认和日志记录后进入系统回收站。v1.7.0 的空文件夹移动需要最终确认。下述清空回收站是需要单独确认的永久删除例外。移入回收站的逻辑大小不等于新增可用空间。不提供自动删除注册表的操作。

v1.7.0 在存储界面顶部新增了“打开回收站”和“清空系统回收站”。后者请求操作系统清空当前用户在已连接驱动器上的整个回收站，包括其他应用丢弃的项目，而非仅所选文件夹。必须经过单独警告、确认复选框和有效期为 2 分钟的一次性确认。不向 AI/CLI/MCP 开放，不预先扫描整个回收站，也不保证释放的空间大小。已在本地 Mac 安装版本中验证警告对话框和取消操作，但未实际清空回收站。

内存清理不会清理系统整体 RAM、其他应用、WebView 辅助进程、交换空间或内存泄漏，也没有 CPU 清理功能。macOS 正常退出应用的请求是独立确认操作，不会回退到强制结束。Windows 性能功能为只读，交换空间为基于提交量的估算值，而非页面文件当前用量。

Docker 管理默认关闭。启用后也仅使用固定命令，排除卷，并单独确认操作不可恢复。

## AI、CLI 与 MCP

v1.8.0 对应源码中，LLM 选择发起性能、已安装应用、搜索、扫描和清理候选查询，分析应用返回的实际列表后再请求必要的补充查询。内置聊天将 CLI 的结构化请求（JSON）交给应用的通用 dispatcher，并不经过外部 MCP 通信链路；外部 MCP 则使用相同的[通用能力契约](docs/architecture/app-capability-contract.md)和应用引擎。变更遵循权限模式、目标重新验证及各操作的确认规则。显示版本为 1.7.0 的 Mac 开发版已分别通过实际 Codex 流程和安装版 sidecar 的只读 stdio 检查，但这不代表 v1.8.0 发布版或所有功能、所有提供商的端到端验证已完成。[实际验证与限制](docs/qa/2026-10-21-installed-chat-audit.md)

安装 Codex 桌面应用并不代表已经安装 Codex CLI。请在应用中检查所用提供商 CLI 的安装、兼容版本和登录状态。Mac 开发版的实测历史范围见上方状态表。虽然也有 Claude Code、Grok、Antigravity、Ollama 适配器，但并未逐一完成实际运行验证。公开 v1.7.0 当时的未验证项保留在其历史发布章节中。

应用聊天会向所选提供商发送包含项目名称和大小的有限文件夹摘要、问题与对话历史。本地 CLI 不意味着模型处理离线进行。MCP 清理工具仅提供匿名候选 ID 和有限摘要，不提供批准或执行删除的工具。另行允许文件或文档搜索后，路径和匹配上下文可能传给外部客户端。最终文件操作仍由应用内的权限与确认规则控制。

## 重要提示：数据丢失与恢复责任

BroomSweepy 设计为只处理用户选择并最终确认的项目。但是，是否能够恢复仍可能受到操作系统权限、回收站设置、同步服务，以及外置或网络驱动器状态的影响。Docker 清理不使用操作系统回收站，已完成的步骤无法恢复。

执行清理前，请备份重要数据，并核对所有选定路径、文件和 Docker 分类。除法律规定不得排除的责任外，项目提供者和贡献者不对用户发起的文件移动、删除、清空回收站或 Docker 清理造成的数据丢失或恢复失败承担责任。
