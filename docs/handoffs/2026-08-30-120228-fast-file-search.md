## Current State Summary
Tauri 공용 데스크톱 앱에 문서 내용 검색과 분리된 `빠른 파일 찾기`를 추가했다. Windows와 macOS에서 동일하게 동작하는 `portableWalk` 공급자가 파일 본문을 열지 않고 이름·경로·종류·확장자·논리 크기·수정 시각을 SQLite FTS5 trigram 카탈로그에 저장한다. 생성 뒤 입력 중 검색, 종류·확장자·크기 필터, 네 가지 정렬, 파일 열기와 위치 표시가 동작한다. 전체 갱신은 취소 가능한 트랜잭션이며 기존 완료 카탈로그를 보존한다. Windows MFT/USN과 macOS FSEvents는 후속 공급자 경계로 남겼다.

### Decisions Made
| Decision | Rationale |
|----------|-----------|
| 파일명·경로 검색과 문서 본문 검색을 별도 화면·DB로 분리 | 빠른 탐색이 문서 파싱 비용과 개인정보 경계를 상속하지 않게 함 |
| 공용 순회 기준선을 먼저 구현 | Windows·macOS 모두 관리자 권한 없이 즉시 사용할 수 있고 OS 가속기 폴백이 됨 |
| SQLite FTS5 trigram 사용 | 기존 의존성과 트랜잭션을 재사용하면서 한글 포함 부분 문자열, 필터, 정렬을 지원 |
| 전체 갱신을 한 트랜잭션으로 수행 | 취소나 실패 시 불완전한 검색 카탈로그를 노출하지 않음 |
| 검색 결과를 삭제 추천과 분리 | 이름·경로 일치는 불필요성이나 삭제 안전성의 근거가 아님 |
| 알려진 앱 내부 이동 뒤 검색 잠금 | 카탈로그의 사라진 경로를 정상 결과처럼 열지 않게 함 |
| MFT/USN은 권한 서비스가 포함된 후속 공급자 | 원시 볼륨 읽기는 Tauri UI 안의 일반 스캔보다 권한·IPC·저널 복구 위험이 큼 |
| Everything은 선택 연동 후보로만 유지 | 설치된 외부 프로세스 의존성을 앱의 기본 기능이나 자동 다운로드로 만들지 않음 |

## Context for Resuming
### Important Context
카탈로그 DB는 Tauri `app_cache_dir()` 아래 `file-catalog-v1.sqlite3` 하나이며 마지막 범위만 보존한다. 검색어 3자 이상은 FTS5 trigram, 1~2자는 이스케이프한 `LIKE`를 사용한다. UI는 100개, 서버는 최대 250개 결과를 허용한다. 외부 프로세스나 셸 문자열을 호출하지 않고 구조화된 Tauri 요청만 사용한다.

현재 `FileCatalogProvider`는 `PortableWalk` 하나다. 불필요한 새 trait 계층은 만들지 않았으며 MFT/USN 구현이 실제로 두 번째 독립 공급자가 될 때 기존 composition point에서 계약을 추출한다. 조사 기준 프로젝트와 링크는 `docs/architecture/fast-file-search.md`에 있다. 특히 AllTheThings는 Rust+Tauri+MIT로 MFT/USN과 권한 서비스를 구현한 직접 참고 사례지만 이번 코드에는 복사하지 않았다.

검증 결과는 코어 33개, Windows 자원 테스트 1개, Tauri 19개 통과이며 실제 휴지통을 움직이는 2개만 의도적으로 ignored다. `cargo fmt --check`, workspace Clippy `-D warnings`, TypeScript 검사, Vite 빌드가 통과했다. 20회 카탈로그 반복 전후는 핸들 `158→158`, 스레드 `3→3`, private bytes `3,813,376→3,887,104`였다. ### Potential Gotchas
- 앱 밖의 파일 변경은 아직 자동 감지하지 않으므로 완료 시각과 수동 업데이트가 신선도 계약이다.
- 전체 볼륨 갱신 트랜잭션은 오래 열릴 수 있으나 검색·다른 스캔은 UI와 `ScanRuntime`에서 동시에 실행되지 않는다.
- 한두 글자 `LIKE`는 수백만 항목에서 trigram보다 느릴 수 있으므로 UI 문구와 결과 상한을 유지한다.
- 항목 상한에 도달하면 순회 순서 일부만 저장되며 UI는 더 작은 범위를 요구해야 한다.
- 운영체제의 단일 `read_dir`·metadata 호출은 협력적 취소로 중간 강제 종료할 수 없다.
- 카탈로그 초기화는 레코드 삭제와 `VACUUM`을 수행하지만 저장장치 포렌식 수준의 완전 삭제를 보장하지 않는다.
- 저장소 기준선 대부분이 아직 untracked이고 `.gitignore`에는 사용자 변경이 있으므로 일괄 정리·리셋하지 않는다.
- 셸 PATH에는 Cargo가 없어 Rust·Tauri 명령 전에 `%USERPROFILE%\.cargo\bin`을 명령 범위 PATH에 추가해야 한다.
