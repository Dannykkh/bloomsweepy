# 앱 기능 계약과 대화형 조사

현재 개발본의 계약이다. GitHub v1.7.0 공개 배포본과 같다는 뜻은 아니다.
이 맥의 개발 설치본에서 확인한 범위는 [공통 MCP 검증 기록](../qa/2026-10-06-common-mcp-results.md)을 따른다.

## 역할

LLM은 사용자 대신 앱을 조작하는 분석자다. 질문에 맞는 앱 조회를 선택하고, 앱이 반환한 실제 결과를 검토하며 추가 조회나 최종 분석을 요청한다. Rust 앱은 목록 생성·필터·정렬·검색·용량 측정·작업 상태·검토 준비 및 최종 실행의 검증을 담당한다. CLI가 자체 파일 검색을 해놓고 앱 결과인 것처럼 반환하는 흐름이 아니다.

삭제 안전성을 이름·크기만으로 보장할 수 없다. 모델의 검토 제안과 삭제 권한은 다르다.
내장 채팅의 파일·빈 폴더·앱 본체/관련 데이터 이동은 정확한 대상을 보여준 뒤 예/아니오
한 번으로 결정한다. 동일한 질문 하나가 대기 중일 때 직접 입력한 명확한 예/아니오도
메인 UI가 로컬 처리하며 AI를 다시 호출하지 않는다. 설정에서 명시적으로 확인 생략을
허용하면 모든 이름을 지정한 단순 직접 파일·폴더·앱 본체 삭제 명령은 재검증 후 처리한다.
정확한 native 대상 이름을 먼저 literal로 식별하고, 남은 전체 문장이 지원하는 직접 명령
형식일 때만 확인을 생략한다. 이름 자체의 조건 단어는 명령 조건이 아니다. 조건·상담·부정·
인용·추가 명령·복합/지원하지 않는 표현·다른 경로·모호한 이름·여러 계획은 기존 예/아니오로
확인하며 자동 실행하지 않는다. 관련 데이터·프로세스 종료·
Docker 정리·영구 삭제는 이 자동 권한에서 제외한다. MCP와 모델에 실행/자동 승인 도구를
주지 않으며 사용자의 질문이 아닌 모델 출력은 어떤 경우에도 승인으로 해석하지 않는다.

파일 계획에 함께 오는 `files.workspace:review_required` 결과는 같은 revision의 인라인
계획 근거이지 두 번째 승인이 아니다. 확인 생략은 native 출처·검토 준비·freshScan·revision이
일치하는 자체 검토 하나와 완료된 조회 결과만 있을 때 허용한다. 다른 검토·불완전 결과·
대상 변경은 자동 실행을 막는다. 로컬 취소·실행·선택 변경은 해당 revision의 자체 대기
근거만 정리하며 다른 기능의 검토를 취소하지 않는다. 취소 결과도 대화에 남긴다.

이 채팅 휴지통 이동 계획은 앱 실행 중 시간만으로 만료되지 않는다. 일회용 소비,
세션·revision·선택·앱 inventory·kind 일치와 실행 직전 신원/내용/실행 상태 검증은 유지한다.
변경·취소·재실행·앱 재시작 후에는 새 계획이 필요하다. 폴더 트리/시스템 정리와 영구
휴지통 비우기의 별도 수명·확인은 이번 변경의 대상이 아니다.

## 정본과 조합

기계가 읽는 정본은 [capabilities.rs](../../crates/bloomsweepy-control/src/capabilities.rs)의 typed 요청·catalog·예제·권한·부분 결과 계약이다. native 프롬프트와 MCP가 이 목록을 직접 소비한다. 내장 `app` 요청과 MCP `app_action`은 [app_tools.rs](../../apps/desktop/src-tauri/src/app_tools.rs)의 같은 dispatcher로 들어간다. 기존 MCP10도구와 native 파일/빈 폴더 요청은 호환을 유지한다.

내장 채팅은 Tauri IPC로 Rust 대화 제어기를 호출하고, CLI 모델이 반환한 strict JSON
`{message, action}`을 파싱한다. 외부 Codex 등은 MCP stdio를 통해 같은 앱 기능을
호출한다. JSON은 데이터 형식이고 MCP는 외부 도구 연결 규약이며, 내장 채팅까지 MCP
wire를 통과시키는 구조는 아니다. 입구가 달라도 실제 조회와 결과의 정본은 앱 엔진이다.

`app_capabilities`는 모든 공통 기능 ID·작동 예제·권한을 보존한 작은 discovery index를
반환한다. 해당 기능의 세부 제약/작업 예제는 `app_action`의
`{"kind":"capability_details","capabilityId":"files.workspace"}`로 읽는다.
index와 각 상세도 일반 결과와 같은16KiB 상한을 적용하며 전송 상한을 해제하지 않는다.
내장 프롬프트에는 전체 정본을 바로 제공하므로 별도의 상세 조회 라운드를 요구하지 않는다.

일반 파일 작업은 공통 `{"kind":"file_workspace","operation":{...}}` 요청이다.
scan/largest/search/review_named/browse/parent/page/select/review/status를 제공하고 기존
내장 `files` envelope는 같은 dispatcher로 연결되는 호환 alias다. 외부 호출은 임의
path/session을 받지 않고 앱에서 선택한 루트에 묶인 독립 작업 공간 하나를 사용한다.
외부의 오래 걸리는 검사/검색/검토는 작업 번호를 즉시 반환하며 `operations.status`로
진행/완료를 확인하고 file_workspace/status로 실제 목록·검토·마지막 처리 결과를 읽는다.
진행 중에는 해당 번호의 간격 둔 상태 관찰을 턴당 최대4회로 제한하는 모델 행동 계약을 둔다.
이는 서버 rate-limit이 아니며, 아직 진행 중이면 새 검사나 자동 실행 대신 대기 상태를 설명한다.
조회 시작과 완료를 혼동하지 않으며 타 내장 대화의 상태/선택/계획은 공유하지 않는다.

시스템/앱 관리, 파일 카탈로그/문서 색인, 공간 검사/정리 후보, Docker 등은 기존 앱 엔진을 재사용한다. 앱에 없는 CPU 청소·SMART 검사·파일시스템 오류 진단·일반 이름 변경/생성/이동은 제공한다고 등록하지 않는다.

## 조사 루프

내장 채팅의 공급자별 모델·Codex 모델별 추론 선택은 [모델 선택 계약](assistant-model-selection.md)을 따른다. 선택 ID와 추론 override 또는 CLI 기본값을 같은 조사 요청의 모든 라운드에 사용하며, 모델/강도 오류 시 자동 전환하지 않는다. 선택은 기능·공개·최종 실행 권한을 변경하지 않는다. 외부 MCP 호출자의 모델·추론 설정은 해당 외부 클라이언트가 정한다.

[조사 도면](../flow-diagrams/app-tool-investigation.mmd)을 따른다. 모델은 라운드마다 action 하나 또는 최종 답변을 반환한다. 앱이 실행한 결과를 다음 라운드 입력에 넣으므로 조회 후 실제 근거로 분석한다. 동일 요청 반복을 거부하고, 최대4행동·누적 결과48KiB·한 결과16KiB·전체 입력192KiB·전체 모델 조사10분 상한을 둔다. CLI stdin은 익명 파일을 사용하여 입력을 읽지 않는 CLI가 파이프를 막고 취소/제한 시간을 무력화하지 못하게 한다.

검토 필요·작업 실행 중·권한 필요·미지원/실패는 추가 행동을 멈춘다. 그 실제 상태를
모델에 전달해 한 번의 분석 전용 응답(`action:null`)으로 대기/제한 이유를 설명한다.
추가 행동이 나오면 실행하지 않고 앱의 상태 안내를 유지한다. 후속 모델 호출/JSON 분석
실패도 이미 받은 실제 결과나 준비된 검토를 버리거나 같은 앱 작업을 다시 실행하지 않는다.
전체5모델호출·4행동·600초 모델 조사 예산 안에서 수행한다. 새 앱 행동 전에도 deadline을 확인한다.
진행 중인 파일 검사는 협력 취소를 사용하며 600초에 강제 종료되는 wall-clock 보장은 아니다.
최종 분석과 실제 결과 카드는 별개이며,
비동기 검사/색인은 작업 번호로 상태를 확인하고 완료와 시작을 혼동하지 않는다.

외부 파일 검토창의 취소는 현재 revision/plan ID와 정확히 일치할 때만 그 계획을 변경한다.
이미 교체·철회·소비된 창의 형식상 유효한 ID는 상태 불변의 닫기로 처리하므로 새 계획이나
실제 처리 결과를 지우지 않는다. 최종 실행은 여전히 현재 신원·권한·일회용 claim을 모두 요구한다.
파일 조회 결과의 `deleted:false`는 해당 조회가 삭제 실행이 아니라는 뜻이다.
이전 이동의 성공·부분 실패·취소는 `lastOperation.outcome/movedCount/movedBytes`의 실제 근거로 판단한다.

## 범위·신선도·공개

대화의 진행 상태는 native `assistant-progress` 이벤트를 통해 CLI 준비, 응답 대기/결과 분석,
앱 조회의 실제 경계에서 표시한다. 선택적 요청 `progressId`와 `sessionId`로 이전 요청의
이벤트를 걸러내고 완료/오류/화면 해제 시 구독을 정리한다. 이벤트에는 단계·라운드·기능 ID만
추가하며 파일 경로·질문·본문·모델 출력은 넣지 않는다. 권한·조회·최종 실행 계약은 바뀌지
않는다. 스트리밍 토큰이나 완료율을 추측하지 않는다. UI 규칙은
[대화 작업면 계약](../design-refs/2026-10-05-experience-chat-workbench.md)을 따른다.

- 내장 파일 조사는 저장된 세션의 선택 루트 안에서 한다. 카탈로그 검색은 선택 session/index root 기준이며 현재 browse 하위 폴더 기준과 다르다.
- 폴더 검사는 별도 허용 스위치를 요구하지 않는다. 메인 앱에서 폴더를 선택하면 정확한 루트와 현재 `ScanConfig`를 기존 main-window 전용 IPC로 연결한다. 외부 MCP는 이 선택 범위만 검사 요청할 수 있으며 모델이 임의 경로를 지정할 수 없다. 폴더 변경은 기존 범위 철회 후 새 범위 연결이고, 연결/저장 실패는 표시하되 기존 범위가 철회됐다면 로컬 앱 검사 자체를 막지 않는다.
- 외부 호출은 인증된 로컬 연결과 기능별 공개 권한이 필요하다. 시스템·앱 조회는 별도 허용이며 기본 꺼짐이다. 문서 일치 본문을 AI에 전달하는 기능은 내장/외부 모두 문서 공개 동의를 요구한다.
- 외부 파일 작업 공간은 정확한 선택 루트/현재 검사 기준의 scope epoch와 정리 허용 epoch에 결속한다. root/config 변경·철회·재허용은 오래된 조회/계획을 재사용하지 못하게 한다. 파일 정리 선택/검토는 별도 정리 검토 허용이 필요하다. 경로·계획 ID는 로컬 검토 카드에만 전달하며 main 앱의 예/아니오로 일회용 계획을 실행/취소한다. 외부 MCP에는 approve/execute나 내장 확인 생략 권한을 제공하지 않는다. 실행/취소/부분 실패 결과도 상태 조회의 실제 근거로 반환한다.
- 전역 시스템 정리 검사·후보·검토는 선택 대화 폴더 밖까지 다루므로 양쪽 모두 정리 검토 허용을 요구한다. 허용을 자동으로 켜지 않는다.
- 모델용 `data`와 로컬용 `presentation`을 분리한다. 새 공통 결과에서 전체 경로·실행 preview/plan ID는 모델 및 직접 Control/MCP 응답에서 제외한다. 문서 검색의 승인된 일치 본문 일부는 공개 예외이며 이름·크기·목록 ID·질문·이력도 공급자에게 전달될 수 있다. 기존 legacy MCP 검색은 허용된 경로/문맥 반환 계약을 유지한다.
- 미측정 Mac 앱/카탈로그 폴더 크기는 null이며0으로 위장하지 않는다. 색인 없음·부분 검사·생략·snapshot/generation·측정 시각을 유지한다. Mac 프로세스는 GUI 앱 집계이며 모든 daemon 목록이 아니다.
- 메모리 정리는 BroomSweepy host allocator의 미사용 페이지만 대상이다. 시스템 RAM·다른 앱·WebView·swap을 청소하지 않는다.

작업 소유권·동의 철회·wire 재전송 검증과 UI/native 런타임 판정은 [QA 기록](../qa/2026-10-04-app-tool-integration.md)에 실제 실행한 범위만 남긴다. 토큰 절감률은 미측정이며 추가 분석 라운드는 토큰을 소비한다.

## 선택적 권한 기억

권한은 기본적으로 모두 꺼져 있고 `session` 수명이다. 메인 앱 화면에서만 `remember`를
선택할 수 있다. 유지 방식 변경은 권한 자체를 켜지 않는다. 추가 확인 없는 내장 채팅
휴지통 이동은 별도 기본 OFF 권한이며 같은 수명을 따른다. Rust가 앱 데이터 폴더의 전용
`permission-settings-v1.sqlite3`에 시스템·앱 공개 여부, 검색의 원래/정규화 루트, 검사 루트와
승인된 `ScanConfig`, 정리 검토 공개 여부와 채팅 확인 생략 선호만 저장한다. 토큰, 진행 작업, 정리 계획, 개별 삭제 승인,
실행 nonce는 이 저장소에 넣지 않는다. MCP/모델에 수명 변경 도구를 제공하지 않는다.

서버 연결을 열기 전에 복원하며 폴더 존재·정규화 대상·검사 기준 상한을 재검증한다.
사라진 폴더, 대상이 바뀐 링크, 유효하지 않은 설정의 범위는 제거해 저장한다. 폴더를 UI에서
바꾸면 기존 검사 범위를 즉시 철회하고 새 선택 범위를 연결한다. 검사 기준은 저장 성공 후
UI와 범위에 함께 반영한다. 기억 모드에서도 변경이 다음 실행에 반영된다. 검색 허용은 기존
색인과 정확히 같은 정규화 루트에서만 유효하다.

새 허용은 저장 성공 후에만 런타임에 적용한다. 철회 저장 실패 시 현재 권한은 제한하고
전용 허용 DB를 폐기해 이전 허용의 재등장을 막는다. 폐기마저 실패하면 복원 가능성을
경고하며 Remember 상태를 유지해 이후 변경에서도 저장/폐기를 재시도한다. 손상·과대·지원하지 않는 저장소는 권한을 복원하지 않고 경고하며, Unix 파일은
사용자 전용 권한으로 제한한다. payload32KiB/DB1MiB 상한을 둔다.

`session` 전환은 디스크의 허용을 지우지만 현재 실행의 허용은 유지한다. 완전 종료 후에는
모두 꺼진다. 창 닫기로 메뉴 막대에 남는 것은 종료가 아니다.
프로세스 종료·Docker·영구 삭제의 최종 확인은 이 권한과 독립이다. [기존 권한 검증](../qa/2026-10-05-remembered-permissions.md)과 [채팅 삭제 확인 QA](../qa/2026-10-05-conversational-trash-consent.md)를 따른다.
운영체제의 전체 디스크 접근 등 OS 권한은 별도이며 이 설정이 대신 부여하지 않는다.
