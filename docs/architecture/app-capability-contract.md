# 앱 기능 계약과 대화형 조사

현재 개발본의 계약이다. GitHub v1.7.0 배포본이나 현재 설치본에 이미 반영됐다는 뜻은 아니다.

## 역할

LLM은 사용자 대신 앱을 조작하는 분석자다. 질문에 맞는 앱 조회를 선택하고, 앱이 반환한 실제 결과를 검토하며 추가 조회나 최종 분석을 요청한다. Rust 앱은 목록 생성·필터·정렬·검색·용량 측정·작업 상태·검토 준비 및 최종 실행의 검증을 담당한다. CLI가 자체 파일 검색을 해놓고 앱 결과인 것처럼 반환하는 흐름이 아니다.

삭제 안전성을 이름·크기만으로 보장할 수 없다. 모델의 검토 제안과 삭제 권한은 다르며, 파일 이동·앱 제거·프로세스 종료·Docker 정리는 정확한 로컬 확인과 사용자 버튼을 유지한다. AI에 영구 휴지통 비우기, 임의 셸, 자동 승인 도구를 주지 않는다.

## 정본과 조합

기계가 읽는 정본은 [capabilities.rs](../../crates/bloomsweepy-control/src/capabilities.rs)의 typed 요청·catalog·예제·권한·부분 결과 계약이다. native 프롬프트와 MCP가 이 목록을 직접 소비한다. 내장 `app` 요청과 MCP `app_action`은 [app_tools.rs](../../apps/desktop/src-tauri/src/app_tools.rs)의 같은 dispatcher로 들어간다. 기존 MCP10도구와 native 파일/빈 폴더 요청은 호환을 유지한다.

시스템/앱 관리, 파일 카탈로그/문서 색인, 공간 검사/정리 후보, Docker 등은 기존 앱 엔진을 재사용한다. 앱에 없는 CPU 청소·SMART 검사·파일시스템 오류 진단·일반 이름 변경/생성/이동은 제공한다고 등록하지 않는다.

## 조사 루프

[조사 도면](../flow-diagrams/app-tool-investigation.mmd)을 따른다. 모델은 라운드마다 action 하나 또는 최종 답변을 반환한다. 앱이 실행한 결과를 다음 라운드 입력에 넣으므로 조회 후 실제 근거로 분석한다. 동일 요청 반복을 거부하고, 최대4행동·누적 결과48KiB·한 결과16KiB·전체 입력192KiB·전체 모델 조사10분 상한을 둔다. CLI stdin은 익명 파일을 사용하여 입력을 읽지 않는 CLI가 파이프를 막고 취소/제한 시간을 무력화하지 못하게 한다.

검토 필요·작업 실행 중·권한 필요·미지원/실패는 명확한 대기/제한 상태로 멈춘다. 최종 분석과 실제 결과 카드는 별개이며, 카드가 있다는 이유로 모델의 분석을 버리지 않는다. 비동기 검사/색인은 작업 번호로 상태를 확인하며 완료와 시작을 혼동하지 않는다.

## 범위·신선도·공개

대화의 진행 상태는 native `assistant-progress` 이벤트를 통해 CLI 준비, 응답 대기/결과 분석,
앱 조회의 실제 경계에서 표시한다. 선택적 요청 `progressId`와 `sessionId`로 이전 요청의
이벤트를 걸러내고 완료/오류/화면 해제 시 구독을 정리한다. 이벤트에는 단계·라운드·기능 ID만
추가하며 파일 경로·질문·본문·모델 출력은 넣지 않는다. 권한·조회·최종 실행 계약은 바뀌지
않는다. 스트리밍 토큰이나 완료율을 추측하지 않는다. UI 규칙은
[대화 작업면 계약](../design-refs/2026-10-05-experience-chat-workbench.md)을 따른다.

- 내장 파일 조사는 저장된 세션의 선택 루트 안에서 한다. 카탈로그 검색은 선택 session/index root 기준이며 현재 browse 하위 폴더 기준과 다르다.
- 폴더 검사는 별도 허용 스위치를 요구하지 않는다. 메인 앱에서 폴더를 선택하면 정확한 루트와 현재 `ScanConfig`를 기존 main-window 전용 IPC로 연결한다. 외부 MCP는 이 선택 범위만 검사 요청할 수 있으며 모델이 임의 경로를 지정할 수 없다. 폴더 변경은 기존 범위 철회 후 새 범위 연결이고, 연결/저장 실패는 표시하되 기존 범위가 철회됐다면 로컬 앱 검사 자체를 막지 않는다.
- 외부 호출은 인증된 로컬 연결과 기능별 공개 권한이 필요하다. 시스템·앱 조회는 별도 허용이며 기본 꺼짐이다. 문서 일치 본문을 AI에 전달하는 기능은 내장/외부 모두 문서 공개 동의를 요구한다.
- 전역 시스템 정리 검사·후보·검토는 선택 대화 폴더 밖까지 다루므로 양쪽 모두 정리 검토 허용을 요구한다. 허용을 자동으로 켜지 않는다.
- 모델용 `data`와 로컬용 `presentation`을 분리한다. 새 공통 결과에서 전체 경로·실행 preview/plan ID는 모델 및 직접 Control/MCP 응답에서 제외한다. 문서 검색의 승인된 일치 본문 일부는 공개 예외이며 이름·크기·목록 ID·질문·이력도 공급자에게 전달될 수 있다. 기존 legacy MCP 검색은 허용된 경로/문맥 반환 계약을 유지한다.
- 미측정 Mac 앱/카탈로그 폴더 크기는 null이며0으로 위장하지 않는다. 색인 없음·부분 검사·생략·snapshot/generation·측정 시각을 유지한다. Mac 프로세스는 GUI 앱 집계이며 모든 daemon 목록이 아니다.
- 메모리 정리는 BroomSweepy host allocator의 미사용 페이지만 대상이다. 시스템 RAM·다른 앱·WebView·swap을 청소하지 않는다.

작업 소유권·동의 철회·wire 재전송 검증과 UI/native 런타임 판정은 [QA 기록](../qa/2026-10-04-app-tool-integration.md)에 실제 실행한 범위만 남긴다. 토큰 절감률은 미측정이며 추가 분석 라운드는 토큰을 소비한다.

## 선택적 권한 기억

권한은 기본적으로 모두 꺼져 있고 `session` 수명이다. 메인 앱 화면에서만 `remember`를
선택할 수 있다. 유지 방식 변경은 권한 자체를 켜지 않는다. Rust가 앱 데이터 폴더의 전용
`permission-settings-v1.sqlite3`에 시스템·앱 공개 여부, 검색의 원래/정규화 루트, 검사 루트와
승인된 `ScanConfig`, 정리 검토 공개 여부만 저장한다. 토큰, 진행 작업, 정리 계획, 삭제 승인,
실행 nonce는 이 저장소에 넣지 않는다. MCP/모델에 수명 변경 도구를 제공하지 않는다.

서버 연결을 열기 전에 복원하며 폴더 존재·정규화 대상·검사 기준 상한을 재검증한다.
사라진 폴더, 대상이 바뀐 링크, 유효하지 않은 설정의 범위는 제거해 저장한다. 폴더를 UI에서
바꾸면 기존 검사 범위를 즉시 철회하고 새 선택 범위를 연결한다. 검사 기준은 저장 성공 후
UI와 범위에 함께 반영한다. 기억 모드에서도 변경이 다음 실행에 반영된다. 검색 허용은 기존
색인과 정확히 같은 정규화 루트에서만 유효하다.

새 허용은 저장 성공 후에만 런타임에 적용한다. 철회 저장 실패 시 현재 권한은 제한하고
전용 허용 DB를 폐기해 이전 허용의 재등장을 막는다. 폐기마저 실패하면 복원 가능성을
경고하며 Remember 상태를 유지해 이후 변경에서도 저장/폐기를 재시도한다. 손상·과대·지원하지 않는 저장소는 권한을 복원하지 않고 경고하며, Unix 파일은
사용자 전용 권한으로 제한한다. payload32KiB/DB1MiB 상한을 둔다.

`session` 전환은 디스크의 허용을 지우지만 현재 실행의 허용은 유지한다. 완전 종료 후에는
모두 꺼진다. 창 닫기로 메뉴 막대에 남는 것은 종료가 아니다. 삭제·앱 제거·프로세스 종료의
최종 로컬 확인은 권한 수명과 독립이다. [검증 범위](../qa/2026-10-05-remembered-permissions.md)를 따른다.
운영체제의 전체 디스크 접근 등 OS 권한은 별도이며 이 설정이 대신 부여하지 않는다.
