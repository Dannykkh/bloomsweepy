# BroomSweepy 빠른 파일 찾기 아키텍처

## 기능 경계

빠른 파일 찾기는 파일을 열지 않고 `이름·전체 경로·종류·확장자·논리 크기·수정 시각`만 로컬 카탈로그에 저장해 검색합니다. 문서 본문을 찾는 `문서 검색`, 실제 바이트를 비교하는 `중복 파일`, 용량 회수 후보를 판단하는 `정리 후보`와 의도적으로 분리합니다.

검색 결과는 파일이나 폴더의 위치를 찾는 탐색 결과이며 삭제 추천이 아닙니다. 외부 공급자, 임베딩, RAG는 이 경로에 포함하지 않습니다. 한 글자와 두 글자도 검색할 수 있지만 큰 카탈로그에서는 세 글자 이상 검색보다 느릴 수 있습니다.

## 현재 파이프라인

1. 사용자가 선택한 폴더가 있으면 그 범위를, 없으면 시스템 볼륨을 기본 범위로 사용합니다.
2. Windows에서 선택 범위가 정확한 NTFS 드라이브 루트이고 원시 볼륨을 읽을 수 있으면 `windowsNtfs`를 선택합니다. 그 밖의 경우에는 `portableWalk`로 자동 전환합니다.
3. `windowsNtfs`는 읽기 전용 볼륨 핸들로 MFT의 파일명·부모 ID·논리 크기·수정 시각을 읽고 하드링크의 여러 경로를 복원합니다. `portableWalk`는 심볼릭 링크를 따라가지 않고 숨김 항목까지 최대 4개 작업자로 순회해 같은 메타데이터 계약을 만듭니다.
4. 앱 캐시의 `file-catalog-v1.sqlite3` 내부 스키마 v2에 한 트랜잭션으로 upsert합니다. 전체 적재 중 FTS 동기화 트리거와 보조 인덱스를 잠시 내리고 항목 저장 뒤 한 번 재구축해 행마다 여러 색인을 갱신하는 비용을 피합니다.
5. `windowsNtfs`는 볼륨 일련번호, Journal ID, 다음 USN과 MFT 레코드 ID를 저장합니다. 다음 수동 업데이트에서는 USN 변경 파일의 최신 MFT 레코드만 반영합니다. 폴더 구조 변경, 저널 교체·유실, 변경량 상한 초과 시 전체 MFT 갱신으로 전환합니다.
6. 이름과 전체 경로는 SQLite FTS5 trigram 색인에 연결합니다. 세 글자 미만은 이스케이프한 `LIKE` 검색으로 폴백합니다.
7. UI는 입력 후 140ms 동안 추가 입력이 없을 때 검색하며, 오래된 비동기 응답이 새 결과를 덮지 못하도록 요청 순번을 확인합니다.
8. 종류, 확장자, 최소 크기와 관련도·이름·크기·수정 시각 정렬을 SQL 단계에서 적용하고 상위 100개만 WebView로 보냅니다.
9. 검색창의 일반 단어·따옴표 문구·제외어, 제한된 `OR`·파일명 `glob:`과 `ext:`·`type:`·`path:`·`size:`·`after:`·`before:` 조건을 구조화한 뒤, 모든 값을 SQLite 매개변수로 전달합니다. 화면 필터와 한 줄 조건은 서로 덮어쓰지 않고 교집합으로 적용합니다.

카탈로그 범위가 바뀌면 이전 결과를 섞지 않습니다. 앱 자체 휴지통 작업으로 파일이 이동된 사실을 알게 되면 검색을 잠그고 업데이트를 요구합니다. 아직 상시 감시 스레드는 없으므로 앱 밖의 변경은 사용자가 `색인 업데이트`를 실행할 때 USN 또는 전체 순회로 반영합니다. UI는 실제 공급자와 `전체 갱신`·`USN 변경분` 모드를 표시합니다.

## 한 줄 검색 문법

공백으로 나눈 일반 단어는 모두 포함해야 하며, `"분기 보고서"`처럼 따옴표로 묶으면 하나의 문구로 검색합니다. `-draft`는 이름과 경로에서 해당 단어를 제외합니다. 대문자·소문자를 구분하지 않는 `OR`는 양쪽의 이름 단어, `path:`, `glob:` 조건을 대안 분기로 묶습니다. `ext:`·`type:`·`size:`·날짜·제외 조건과 화면 필터는 분기 밖의 전역 교집합입니다. 예를 들어 `invoice OR receipt ext:pdf -draft`는 초안이 아닌 PDF 중 이름이나 경로에 invoice 또는 receipt가 있는 항목을 찾습니다.

괄호와 중첩 논리식은 지원하지 않고 `OR` 분기를 최대 8개로 제한합니다. 각 분기에는 FTS로 먼저 후보를 줄일 수 있도록 세 글자 이상의 이름·경로 문구 또는 세 글자 이상의 고정 문자열을 가진 `glob:`이 필요합니다. 한두 글자 일반 검색은 `OR` 없이 사용할 수 있습니다. 제외 조건만으로 전체 카탈로그를 훑는 쿼리는 허용하지 않으며 일반 단어 또는 양의 조건을 하나 이상 요구합니다.

| 구문 | 의미 | 예시 |
|---|---|---|
| `OR` | 이름 단어·`path:`·`glob:` 대안 분기, 최대 8개 | `invoice OR receipt` |
| `glob:` | 파일명만 `*`·`?` 패턴으로 검색, 경로 구분자 불가 | `glob:report-*.pdf` |
| `ext:` | 확장자 하나 또는 쉼표 목록 | `ext:pdf,jpg` |
| `type:` | `file`, `folder`, `symlink`, `other` | `type:file` |
| `path:` | 전체 경로에 반드시 포함할 문구 | `path:"Team Files"` |
| `size:` | `>`·`>=`·`<`·`<=`·`=` 또는 포함 범위, B·KB·MB·GB·TB | `size:>100mb`, `size:10mb..1gb` |
| `after:` | 해당 로컬 날짜 00:00 이후 또는 같은 시각 | `after:2026-01-01` |
| `before:` | 해당 로컬 날짜 00:00 미만 | `before:2027-01-01` |
| 앞의 `-` | 일반 단어·`path:`·`glob:`·`ext:`·`type:` 제외 | `-draft`, `-glob:*copy*`, `-ext:tmp` |

날짜 경계는 검색 시 WebView가 전달한 현재 PC 시간대 오프셋으로 계산합니다. 검색어 전체는 256자, 토큰은 32개로 제한합니다. 세 글자 이상인 포함 단어와 경로 조건은 FTS trigram을 사용하고, 한두 글자와 제외 조건은 이스케이프한 `LIKE`로 검사합니다. `glob:`은 파일명 전체에만 적용하며 `*`는 임의 길이, `?`는 문자 하나를 뜻합니다. 고정 문자열을 FTS 이름 열로 먼저 좁힌 뒤 매개변수화된 `LIKE`로 패턴을 다시 확인하므로 무제한 전체 스캔 glob은 허용하지 않습니다. 동적으로 만드는 SQL 조각은 고정된 열·연산자·자리표시자뿐이며 사용자 문자열을 SQL이나 셸에 이어 붙이지 않습니다.

## 트랜잭션과 취소

카탈로그 갱신은 기존 완료 데이터와 새 세대를 같은 SQLite `IMMEDIATE` 트랜잭션 안에서 처리합니다. 사용자가 취소하거나 순회·DB 작업이 실패하면 트랜잭션이 롤백되어 직전 완료 카탈로그가 그대로 남습니다. 완료 커밋 뒤 WAL을 체크포인트합니다.

카탈로그 생성·검색·초기화는 기존 `ScanRuntime` 계약을 사용합니다. 생성은 저장공간 스캔, 문서 색인, 휴지통 이동과 동시에 실행되지 않습니다. 검색도 쓰기 작업 중에는 거절합니다. 블로킹 파일 작업과 SQLite 작업은 Tauri의 블로킹 작업자에서 실행해 React/WebView 스레드를 막지 않습니다.

## 상한과 개인정보

| 항목 | UI 또는 기본값 | 절대 상한 |
|---|---:|---:|
| 카탈로그 항목 | 2,000,000 | 5,000,000 |
| 기록할 접근 이슈 | 100 | 1,000 |
| 검색어 | 256자 | 256자 |
| 검색 결과 | 100 | 250 |
| 순회 작업자 | CPU에 따라 최대 4 | 4 |
| 진행 이벤트 | 512개 항목 또는 100ms | 더 자주 보내지 않음 |

DB에는 본문이나 해시가 아니라 파일시스템 메타데이터만 남습니다. `secure_delete=ON`과 WAL 체크포인트를 사용하지만 저장장치·백업·포렌식 수준의 완전 삭제를 보장하지는 않습니다. 카탈로그 비우기는 별도의 두 번 누르기 확인을 거쳐 레코드를 지우고 `VACUUM`합니다.

## 공급자 상태와 로드맵

두 공급자는 같은 검색 요청·결과 계약과 SQLite 저장소를 사용합니다.

1. 현재 Windows NTFS: 정확한 드라이브 루트에서 MFT로 초기 카탈로그를 만들고 USN 위치를 저장해 파일 변경분만 반영합니다. 권한이 없거나 NTFS가 아니거나 하위 폴더 범위면 자동으로 공용 순회로 폴백합니다.
2. Windows 권한 서비스: 일반 사용자 앱이 관리자 권한을 계속 보유하지 않도록 읽기 전용 원시 수집만 담당하는 최소 권한 서비스와 검증된 IPC를 추가합니다.
3. Windows 선택 연동: 설치된 Everything의 IPC를 명시적으로 사용하도록 사용자가 켠 경우에만 외부 공급자로 조회합니다.
4. macOS APFS: 공용 초기 순회 뒤 FSEvents로 변경 경로를 반영합니다. 이벤트 누락·루트 변경 시 전체 갱신으로 폴백합니다.
5. 검색 문법 후속: 비용 상한을 정의한 regex와 날짜 선택 UI를 검토합니다. 문자열을 셸에 넘기지 않고 구조화 요청으로 유지합니다.

현재 원시 공급자는 앱 프로세스가 볼륨을 읽을 수 있을 때만 활성화되고 실패하면 공용 공급자로 전환합니다. 후속 권한 서비스도 읽기 전용 카탈로그 생성만 담당하며 파일 열기·이동·삭제는 일반 사용자 Tauri 프로세스의 기존 안전 계약을 거쳐야 합니다.

## 검증

코어 테스트는 한글 이름·경로 검색, 종류·확장자·크기·정렬, 구조화 토큰·따옴표·제외어·날짜·시간대·`OR`·파일명 glob·잘못된 문법, 화면 필터와의 교집합, 삭제 경로 갱신, 취소 롤백, v1→v2 마이그레이션, 결과·항목 상한, MFT 경로 복원과 USN 중복 제거를 확인합니다. Windows 자원 회귀 테스트에서 64개 fixture의 카탈로그 생성과 검색을 예열한 뒤 20회 반복했을 때 핸들 `158 → 158`, 스레드 `3 → 3`, private bytes `3,813,376 → 3,887,104`를 관찰했습니다.

관리자 권한 Windows 호스트의 실제 NTFS 시험에서는 MFT 열거와 Journal 조회가 3.03초, 1,000개 제한 카탈로그 생성·검색이 3.14초에 통과했습니다. 가장 작은 쓰기 가능 NTFS 볼륨을 고른 종단간 시험은 전체 카탈로그 생성 뒤 새 파일을 만들고 다음 실행에서 USN 변경분으로 검색되는 것까지 29.51초에 통과했습니다. 이 수치는 2026-08-30 해당 호스트의 회귀 기록이며 다른 디스크의 파일 수와 하드웨어 성능을 보장하지 않습니다.
