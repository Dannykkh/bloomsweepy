# MCP 정리 검토 v3

> 상태: Windows 구현·패키징 검증 완료, macOS 패키징은 CI 확인 필요
>
> 작성일: 2026-09-02

## 목적과 책임

Codex와 Claude Code는 사용자의 요청을 요약하고 BroomSweepy의 명시적 도구를 선택합니다. 파일 탐색, 검사 결과 보관, 항목 동일성 재검사, 작업 기록과 운영체제 휴지통 이동은 실행 중인 BroomSweepy 앱이 담당합니다.

이 경계는 BroomSweepy 도구 호출에 적용됩니다. Codex나 Claude Code 자체에 이미 파일시스템 도구와 운영체제 권한이 있다면 그 권한까지 제거하지는 않습니다. 사용자는 공급자의 별도 권한도 따로 관리해야 합니다.

## 선택한 구조

| 안 | 장점 | 위험 | 판정 |
|---|---|---|---|
| 원시 파일 목록을 모델에 전달 | 구현이 단순함 | 경로·이름 노출과 토큰 사용량 증가 | 제외 |
| MCP가 직접 삭제 | 대화 안에서 끝남 | 승인 우회, 재전송과 오판 위험 | 제외 |
| 익명 후보 요약 → 앱 확인 계획 → 앱 최종 승인 | 경로와 실행 권한을 앱에 유지 | 앱과 공급자의 두 단계 상호작용 필요 | 채택 |

토큰 사용량은 일반적으로 원시 파일 목록이나 스캔 로그를 대화에 넣는 방식보다 줄어듭니다. 기본 20개, 최대 50개의 고정 필드 요약만 전달하기 때문입니다. 실제 절감량은 공급자와 대화 길이에 따라 달라 보장값으로 표시하지 않습니다.

## 공개 MCP 계약

정리 관련 공개 도구는 다음 세 개뿐입니다.

| 도구 | 입력 | 출력 | 파일 변경 |
|---|---|---|---|
| `cleanup_candidates` | 출처, 검사 번호, 위치, 최대 개수 | 익명 후보 요약 | 없음 |
| `create_cleanup_plan` | 출처, 검사 번호, 후보 번호 1~50개 | 계획 번호와 대기 상태 | 없음 |
| `cleanup_plan_status` | 계획 번호 | 제한된 상태·결과 집계 | 없음 |

MCP 스키마에는 raw 경로, 파일 이름, 내용 해시, 승인 여부나 실행 동사가 없습니다. 정리 후보 요약은 종류, 신뢰도, 논리 용량, 항목 수, 비활성 기간, 이유 코드와 앱 실행마다 바뀌는 32자리 후보 번호만 포함합니다. 중복 그룹은 복사본 수, 낭비 용량, 서로 다른 폴더 여부와 전체 내용 검증 여부만 포함합니다.

파일·문서 검색은 사용자가 별도로 허용한 경우 경로와 일치 문맥을 반환할 수 있습니다. 정리 후보의 경로 비공개 계약과 검색 권한을 혼동하지 않습니다.

## 확인 계획 수명주기

1. 앱에 완료된 시스템 정리 또는 중복 검사 결과가 있어야 합니다.
2. 사용자가 현재 앱 실행에서 정리 계획 검토를 별도로 허용합니다.
3. 후보 번호는 출처, 검사 번호, 결과 안의 위치와 무작위 비밀값을 keyed BLAKE3로 묶어 만듭니다.
4. 같은 후보 집합의 재전송은 기존 계획 번호를 반환합니다. 다른 계획이 대기 중이면 새 계획을 만들지 않습니다.
5. 계획은 메모리에만 최대 5분 보관하며 앱 재시작 뒤 복원하지 않습니다.
6. 앱이 정확한 경로와 이유를 표시합니다. 검토 필요 항목은 별도 확인 없이는 실행하지 않습니다.
7. 앱 전용 승인 명령이 계획을 한 번만 실행 상태로 바꿉니다. MCP에는 이 명령이 없습니다.
8. 검사 번호와 후보가 바뀌었거나 파일 사전검사가 실패하면 계획을 오래된 상태로 끝내고 아무 항목도 이동하지 않습니다.
9. 성공한 요청은 기존 휴지통 사전검사, 항목별 직전 재검사, 동기화 작업 기록과 운영체제 휴지통 경계를 사용합니다.

중복 그룹은 전체 해시와 바이트 비교를 통과한 결과만 사용하며 결정적인 보관본 하나를 남깁니다. 한 계획에서 실제 이동할 파일은 최대 50개입니다.

## 앱과 공급자 연결

Windows 설치본은 `bloomsweepy-mcp.exe`를 Tauri sidecar로 포함합니다. 설정 화면은 Codex와 Claude Code의 공식 CLI로만 명시적으로 등록·조회·해제하며 설정 파일을 직접 수정하지 않습니다. 기존 `bloomsweepy` 연결이 앱의 로컬 영수증과 다르면 덮어쓰거나 제거하지 않습니다.

연결 통로는 loopback TCP와 앱 실행마다 새로 만든 토큰을 사용합니다. 설명자와 단일 실행 잠금은 현재 사용자 데이터 폴더에 둡니다. 이는 네트워크 외부 접근을 막지만, 같은 Windows 사용자로 실행되는 악성 프로세스까지 강하게 격리하는 보안 경계는 아닙니다. Windows 설명자 DACL 강화는 후속 보안 작업입니다.

## 검증

2026-09-02에 다음 외부 신호를 확인했습니다.

- `cargo check --workspace`
- `cargo clippy --workspace --all-targets -- -D warnings`
- `cargo test --workspace`
- `npm run check`, `npm run build`과 모든 프런트 정책 테스트
- 50개 응답 예산, 경로·이름 비노출, 후보 번호·검사 번호 결합, 중복 보관본 유지 회귀 테스트
- MCP 표준 초기화와 `tools/list`: 전체 10개, 정리 도구 3개, 승인·실행 도구 0개
- Windows MSI와 NSIS 설치 EXE 빌드 및 두 패키지의 `bloomsweepy-mcp.exe` 포함 확인

실제 사용자 Codex·Claude 설정 변경은 자동 테스트에서 수행하지 않았습니다. 릴리스 앱의 설정 화면에서 사용자가 변경 경로를 확인한 뒤 실행하는 수동 검증 대상입니다. macOS `.app`·DMG 포함과 코드 서명은 macOS CI 또는 실제 Mac에서 확인해야 합니다.
