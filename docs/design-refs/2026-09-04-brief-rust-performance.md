# Design Brief: Rust Performance Instrument

## Decision

- Rust/Tauri에 실제 CPU·메모리 상태와 상위 프로세스를 보여 주는 `성능` 화면을 추가한다.
- SwiftUI의 넓은 글래스 카드, 큰 수치, 원클릭 흐름은 따른다. 메모리 정리는 macOS에서 BroomSweepy 자체 allocator 반환으로 복원하되 하드코딩된 앱 등급과 메모리 압박 방식은 이식하지 않는다.
- 첫 릴리스의 종료 기능은 macOS 일반 GUI 앱에 보내는 정상 종료 요청만 지원한다. 강제 종료와 프로세스 트리 종료는 범위 밖이다.

## User Evidence

- “swift 에 보면 메모리 정리하기 기능도 있지 않나? cpu정리나 사용량 파악도??”
- “swift의 ui ux 및 기능이 괜찮은거 같음. 대부분 원클릭에 아이콘과 화면이 시원시원하잖아.”
- “러스트가 기본 프로젝트로 갈꺼야. 여기에 swift를 합쳐야 할듯 한데.”

## Primary Task

사용자가 느려짐의 원인을 실제 CPU·메모리 수치와 프로세스별 사용량으로 확인하고, 저장하지 않은 작업 경고를 본 뒤 선택한 일반 앱 하나에만 정상 종료를 요청한다.

## Observable Success

- 첫 진입 후 실제 CPU·RAM 값과 마지막 측정 시각을 5초 안에 이해한다.
- 첫 CPU 샘플 준비, 정상, 오래됨, 오류 상태가 구분된다.
- 종료 전에 서버가 대상 신원을 다시 확인하며 PID 재사용·자기 자신·다른 사용자·시스템 프로세스를 거부한다.
- UI는 종료 요청 전 앱 이름과 저장하지 않은 작업 경고를 표시하고 취소에 기본 포커스를 둔다.
- 1280×820과 760×600에서 핵심 수치와 종료 행동이 잘리지 않는다.

## Non-goals

- 메모리를 일부러 점유했다 해제하는 방식이나 시스템 전체 여유 메모리 변화로 `확보한 메모리`를 주장하지 않는다.
- CPU를 정리하거나 자동으로 앱을 종료한다고 표현하지 않는다.
- 강제 종료, 프로세스 트리 종료, 임의 PID 입력, 명령행·환경변수 수집은 하지 않는다.
- macOS 이외 플랫폼에서 불안전한 raw PID 종료를 폴백으로 사용하지 않는다.

## Adapter Status

- Product Design plugin: `ABSENT`.
- Adapter: local React/Tauri implementation.
- 기존 SwiftUI 화면을 사용자가 선택한 golden master로 사용하며 외부 생성 어댑터는 사용하지 않는다.
