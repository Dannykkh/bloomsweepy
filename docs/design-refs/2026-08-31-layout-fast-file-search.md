# Layout Blueprint: Fast File Search

## Wide Desktop — 1280×820

```text
┌──────────────────────┬───────────────────────────────────────────────────────────────┐
│ Brand                │ 화면 제목·설명                         현재 스캔 범위        │
│                      ├───────────────────────────────────────────────────────────────┤
│ Dashboard            │ 검색 약속·로컬 근거                                         │
│ Fast File Search     │ [ 질의 입력                                             상태 ]│
│ Document Search      │ 문법 토큰                                                     │
│ Cleanup Candidates   │ [종류] [확장자] [크기] [정렬]                                │
│ Space Cleanup        ├───────────────────────────────────────────────────────────────┤
│ Duplicates           │ 파일 목록 위치·새로고침 정보                관리 행동          │
│ Settings             ├───────────────────────────────────────────────────────────────┤
│                      │ 결과 제목·개수·시간                                          │
│ Volume status        │ 파일 정체성·경로                         크기·시각·위치 표시   │
└──────────────────────┴───────────────────────────────────────────────────────────────┘
```

- 셸: `216px minmax(0, 1fr)`, 높이 `100dvh`, 외부 overflow hidden.
- 메인: 전체 남은 폭, `overflow-y:auto`, 수평 overflow 없음.
- 콘텐츠: 좌우 분할 대시보드가 아니라 검색→신뢰→결과의 단일 열.
- 첫 뷰포트: 검색 명령과 파일 목록 상태, 적어도 첫 결과 행까지 우선한다.

## Compact Desktop — native minimum window

```text
┌────────┬──────────────────────────────────────────┐
│ icon   │ 화면 제목                     범위       │
│ rail   ├──────────────────────────────────────────┤
│        │ 검색 약속                                │
│        │ 로컬 전용                                │
│        │ [ 질의 입력 ]                            │
│        │ [ 검색 상태 ]                            │
│        │ 문법 토큰                                │
│        │ [ 종류 전체 폭 ]                         │
│        │ [ 확장자 ]                               │
│        │ [ 크기 ]                                 │
│        │ [ 정렬 ]                                 │
│        │            세로 스크롤 ↓                 │
└────────┴──────────────────────────────────────────┘
```

- 920px 이하: 72px 레일, 콘텐츠 폭 우선.
- 680px 이하: 레일을 오버레이 내비게이션으로 교체.
- 검색 상태는 입력 아래 전폭, 필터는 한 열, 결과 메타는 정체성 아래로 이동.
- 좁은 창에서 숨기는 핵심 정보는 없으며 보조 상세만 `details`로 접는다.

## State Placement

| State | Placement | Layout behavior |
|---|---|---|
| no catalog | 검색 입력 비활성 + 파일 목록 상태 + 방식 설명 | `파일 목록 만들기`를 상태 영역에서 강조 |
| building | 파일 목록 상태 영역 | 300ms 뒤 4개 쉬운 지표, compact에서 2×2 |
| scope changed/stale | 검색과 파일 목록 상태 사이 | 이유와 새로고침 행동을 같은 행에 배치 |
| query error | 상태·근거 다음, 결과 이전 | 결과를 덮지 않고 수정 후 즉시 복구 |
| result | 파일 목록 정보 다음 | 반복 행 정렬, main-only scroll |

## Structural Invariants

- `.app-shell`의 오른쪽·아래 경계는 실제 WebView client rect와 일치한다.
- 1280px 기본 창에서 72px 레일 규칙이 활성화되지 않는다.
- 작은 창 검증을 위해 `Emulation.setDeviceMetricsOverride`를 사용하지 않는다.
- 빈 상태는 스크롤이 없어도 정상이며, 긴 상태는 세로 스크롤로 마지막 행동까지 접근한다.
- 모든 수평 그룹은 컨테이너 쿼리에서 재배치되고 수평 스크롤을 만들지 않는다.
