# Design Brief: Rust 기반 Swift 경험 통합

## Decision

- 배포 기준과 기능 코어는 Rust/Tauri 하나로 유지한다.
- 기존 SwiftUI 앱은 런타임 의존성이 아니라 UI·UX와 기능 우선순위를 판단하는 golden master다.
- 첫 구현은 사용자가 가장 큰 차이라고 지적한 대시보드, 사이드바, 네이티브 글래스 재질에 집중한다.

## User Evidence

- “swift ui가 확실히 훨씬 깔끔한데. 먼저 이 ui부터 따라가야할듯?”
- “대부분 원클릭에 아이콘과 화면이 시원시원하잖아.”
- “글래스모피즘 디자인이라서 더 다르지”
- “러스트가 기본 프로젝트로 갈꺼야. 여기에 swift를 합쳐야 할듯 한데.”
- “여러개일경우 메인으로 큰 카드뷰 보기 옆에 작은 카드뷰로 각 드라이브의 원이 보이고, 클릭하면 그 카드뷰가 커지고 다른 카드뷰는 작게 보이게 되는 그런 스윕(?) 에니메이션?”

## Problem

현재 Rust 대시보드는 드라이브 표, 최근 정리, 최근 파일을 동시에 보여 주어 기능은 많지만 첫 시선의 초점이 없다. CSS 글래스는 불투명 창 위에 놓여 재질 차이가 작고, 동일한 파란 메뉴와 반복 설명은 Swift의 큰 색상 아이콘과 여유 있는 카테고리 리듬보다 복잡하게 느껴진다.

## Primary Task

앱을 연 사용자가 현재 디스크 상태를 한눈에 이해하고, 한 번의 클릭으로 전체 검사 또는 정리 후보 검사를 시작한 뒤 안전한 검토 화면으로 이어진다.

## Milestone Scope

1. macOS에서는 Rust/Tauri 창에 네이티브 vibrancy를 적용하고, 미지원 환경은 불투명 단층 표면으로 폴백한다.
2. Swift와 같은 220px 안팎의 카테고리 사이드바, 큰 색상 아이콘, 하나의 활성 행을 만든다.
3. 대시보드를 큰 저장공간 링과 한 개의 주 CTA가 지배하는 구조로 바꾼다.
4. 정리 후보, 큰 파일, 중복 파일, 파일 찾기를 큰 원클릭 타일로 연결한다.
5. 실제 Rust 보고서만 요약하고 기존 최근 정리·최근 파일은 하단 보조 영역으로 보존한다.
6. 스캔, 재검증, 휴지통, 작업 저널의 Rust 안전 계약은 변경하지 않는다.
7. 여러 물리 드라이브는 시스템 드라이브 한 개를 큰 카드로 시작하고, 나머지는 작은 원 카드로 옆에 배치한다. 작은 카드를 누르면 검사 없이 큰 카드와 역할만 교대한다.

## Non-goals

- Swift 런타임이나 SwiftUI 뷰를 Rust 앱에 포함하지 않는다.
- 근거 없는 건강 점수, 메모리 정리, 악성코드 안전 판정을 복제하지 않는다.
- 일반 큰 파일을 자동 삭제하거나 여러 결과의 용량을 중복 합산해 `정리 가능 용량`으로 표시하지 않는다.
- 초기 대시보드 단계에서는 Swift의 속도·보안·개인정보 화면을 근거 없는 빈 Rust 메뉴로 만들지 않는다.

### Approved scope delta — 성능 화면

사용자가 후속으로 CPU·메모리 상태와 앱 종료 흐름의 Rust 구현을 승인했다. 따라서 성능 화면만 별도 Experience Contract에 따라 실제 런타임 수치와 macOS 정상 종료 요청으로 구현한다. 보안·개인정보 화면은 여전히 이 마일스톤 범위 밖이며, Swift의 메모리 압박 기반 `purgeMemory`는 이식하지 않는다.

- **참조**: [성능 화면 계약](2026-09-04-experience-rust-performance.md), [구현 로그](2026-09-04-impl-log-rust-performance.md)

## Observable Success

- 1280×820에서 첫 5초 안에 디스크 상태와 `전체 검사 시작`을 찾는다.
- 760×600에서 14px 글자와 44px 행동 타깃을 유지하며 가로 넘침 없이 핵심 기능에 접근한다.
- macOS 설치 빌드에서 창 뒤의 바탕이 사이드바와 주 작업면에 실제로 비치며, CSS blur가 중첩되지 않는다.
- 전체 검사와 정리 후보 검사가 대시보드에서 한 번의 클릭으로 시작되고 취소·실패·완료 상태가 구분된다.
- 기존 TypeScript 및 Rust 테스트와 실제 macOS 설치 실행이 통과한다.
- 다중 드라이브 fixture에서 작은 카드 선택 후 선택한 드라이브가 큰 카드가 되고, 이전 큰 카드는 작은 카드로 돌아가며 키보드 포커스가 유지된다.

## Adapter Status

- Product Design plugin: 설치 가능하지만 현재 설치되지 않음 (`ABSENT`).
- Adapter: local React/Tauri implementation.
- Reason: 사용자가 선택한 프로젝트 소유 Swift 화면과 소스가 정확한 레퍼런스이며, 외부 생성 어댑터 없이 동일 계약을 구현할 수 있다.
