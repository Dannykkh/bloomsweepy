# 구현 기록: 단순 용량 관리와 AI 도우미 분리

## 선택한 방향

- 세 후보 가운데 A안인 `안내 우선 용량 지도`를 채택했다.
- 전역 메뉴를 `용량 관리`, `파일 이름 찾기`, `문서 내용 찾기`, `AI 도우미`, `설정` 다섯 개로 줄였다.
- `큰 파일`, `중복 파일`, `정리 후보`는 서로 다른 시작점이 아니라 한 번의 자세한 검사 결과를 보는 용량 관리 내부 탭으로 묶었다.
- 기본 화면에서 CLI 연결 상태와 권한 패널을 제거하고 선택형 `AI 도우미` 화면으로 옮겼다.
- 실제 대화창처럼 보이는 가짜 입력창은 만들지 않았다. 현재 구조는 설치한 로컬 CLI가 MCP 제어 도구를 통해 앱에 요청하는 방식임을 그대로 설명한다.

## 트리맵 명칭과 위치

- 일반 명칭은 `저장공간 트리맵(storage treemap)`이다.
- 기존 SwiftUI 구현은 `slice-and-dice treemap`, 현재 Tauri 구현은 균형 잡힌 재귀 이분할 방식의 `binary treemap`에 가깝다.
- 사용자 화면의 큰 제목은 쉬운 표현인 `폴더 용량 지도`로 유지하고, 패널 눈썹 제목에 정확한 기술명 `저장공간 트리맵`을 함께 표시한다.
- 첫 진입은 `폴더 선택 → 용량 지도 → 큰 파일·중복` 3단계로 안내한다. 지도가 준비된 뒤에는 안내 카드를 축약해 실제 사각형 지도가 첫 화면에 들어오게 했다.

## 접근성과 반응형

- 보이는 본문·레이블의 최소 계산 글자 크기는 14px였다.
- 마우스로 검색 입력칸을 눌렀을 때 큰 외곽 포커스 상자를 제거했다. 키보드 `Tab` 포커스에는 입력 묶음에 한 겹의 1px 액센트 테두리와 1px 내부선만 남겼다.
- 최소 창에서 발견된 60px 가로 넘침은 용량 화면 부모를 컨테이너로 지정해 680px 이하에서 안내 영역이 한 열로 바뀌도록 수정했다.
- 아이콘형 사이드바에서는 hover와 키보드 포커스 설명을 유지하고, 14px 기준을 지켰다.
- 애니메이션은 기존 `transform`과 `opacity` 전환을 유지하고 `prefers-reduced-motion` 계약을 바꾸지 않았다.

## 디자인 절차 상태

- Experience Contract: 완료 및 검증 스크립트 통과.
- 정적 방향 후보: A/B/C 세 안 생성 후 A 채택.
- 실제 렌더 검토: 완료.
- Product Design Gate: `UNKNOWN`. 현재 환경에서 정확히 대응하는 제품 디자인 심사 플러그인을 찾지 못해, 저장소 디자인 정본과 실제 Tauri 렌더 계측으로 대체했다.
- 웹 랜딩 페이지 모션 서사: 데스크톱 데이터 도구 화면이라 적용 대상이 아니다.
