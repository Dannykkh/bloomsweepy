## Page Goal

- 사용자가 이 화면에서 달성할 결과: 폴더를 선택하고 큰 사각형을 따라 용량 원인을 찾은 뒤 큰 파일·중복·정리 후보로 이동한다.
- 제품이 얻어야 하는 결과: 선택 기능인 AI 연결이 기본 저장공간 과업을 방해하지 않는다.
- 관찰 가능한 성공 조건: 첫 화면에서 다음 행동을 찾고, 트리맵 드릴다운과 결과 화면 이동을 완료한다.

## Audience and Tasks

- 주요 사용자와 사용 상황: 디스크가 가득 찼지만 어떤 기능부터 써야 할지 모르는 개인 사용자.
- 최우선 과업: 검사할 폴더 선택, 용량 지도 생성, 큰 폴더 탐색.
- 시작 조건과 완료 조건: 폴더 선택 전부터 시작하며 용량 원인 위치를 확인하고 정리 화면으로 이동하면 완료한다.
- 주요 불안·마찰·실패 가능성: 서로 다른 검사 종류, 비활성 버튼, 삭제 오인, CLI 자동 연결 오인.

## Header and Navigation

- 브랜드·현재 위치·전역 이동·주 행동의 순서: 브랜드 → 용량 관리 → 파일 이름 찾기 → 문서 내용 찾기 → 선택 기능인 AI 도우미 → 설정.
- 데스크톱 내비게이션: 최상위 메뉴 5개, 용량 관리 안에 용량 지도·큰 파일·중복 파일·정리 후보 탭.
- 모바일 대체 구조: 920px 이하 아이콘 레일, 680px 이하 오버레이를 유지하며 하위 탭은 2열 또는 가로 폭 안에서 재배치한다.

## Core Message

- 핵심 약속: 폴더를 고르고 큰 사각형부터 따라가면 용량이 늘어난 위치를 찾을 수 있다.
- 설명: 지도는 폴더 크기, 자세한 검사는 큰 파일과 실제 중복을 찾는다.
- 증거: 실제 경로, 면적 비율, 파일 수, 크기, 마지막 검사 결과.
- 사용자가 다음에 이해해야 할 것: 정리는 결과를 선택한 뒤 별도 확인을 거쳐 휴지통으로 이동한다.

## Section Order

1. 용량 관리 하위 탭: 현재 작업과 관련 기능의 관계를 먼저 보여준다.
2. 시작 안내: 폴더 선택 → 지도 → 자세한 검사의 3단계를 보여준다.
3. 폴더 용량 지도: 주 결과와 드릴다운을 첫 작업면에 둔다.
4. 다음 결과: 큰 파일·중복·정리 후보로 이동한다.
5. 컴퓨터 전체 분류: 필요할 때만 펼치는 선택 상세다.

## CTA Strategy

- Primary: 상태에 따라 `폴더 선택`, `폴더 용량 지도 만들기`, `큰 파일·중복 찾기` 중 하나만 표시한다.
- Secondary: `폴더 바꾸기`, 결과 화면 이동, `컴퓨터 전체 분류`.
- 반복 규칙: 같은 작업면에 primary solid 버튼은 하나만 둔다.
- 완료·실패 피드백: 해당 단계 바로 아래에서 원인과 다음 행동을 표시한다.

## Trust Strategy

- 사용자가 불안을 느끼는 지점: 검사 시작, 정리 후보 선택, AI 연결 허용.
- 그 직전에 제시할 근거: 읽기 전용 여부, 실제 범위, 휴지통 이동 여부, 로컬 MCP 책임 경계.
- 출처·날짜·검증 가능성: 런타임 경로와 보고서, 현재 제어 상태를 사용한다.
- 근거가 없을 때 생략할 요소: 자동 정리 점수, 자동 AI 연결, 설치 완료 표시는 생략한다.

## Desktop Structure

- 기준 뷰포트: 1280×820, 최소 창 760×600.
- 첫 뷰포트: 하위 탭, 3단계 시작 안내, 폴더 용량 지도 헤더와 시작 행동.
- 그리드·pane·콘텐츠 위계: 216px 사이드바 + 단일 메인 열; 트리맵 결과만 지도와 순위 2분할.
- 스크롤 흐름과 밀도 변화: 시작 안내와 지도는 먼저, 결과 이동과 전체 드라이브 상세는 뒤로 보낸다.

## States

| State | Trigger | User sees | Available action | Recovery |
|---|---|---|---|---|
| loading | 폴더 또는 상세 검사 실행 | 현재 단계와 처리량 | 취소 | 이전 완료 결과 유지 |
| empty | 폴더 미선택 또는 결과 없음 | 필요한 선행 조건과 한 개의 다음 행동 | 폴더 선택·검사 | 같은 화면에서 이어서 진행 |
| error | 권한·I/O·연결 오류 | 실패 원인과 영향을 받은 단계 | 다시 시도·폴더 변경 | 다른 기본 기능은 계속 사용 |
| success | 지도 또는 상세 검사 완료 | 지도·결과 수·다음 화면 | 드릴다운·결과 보기 | 파일 변경 시 다시 검사 |
| disconnected | 로컬 CLI 미연결 | 기본 기능은 정상이라는 안내 | 등록 문서 확인 | 연결 없이 앱 계속 사용 |

## Performance Budget

- 첫 화면 필수 자산: 기존 CSS, Pretendard, Lucide, 시스템 볼륨 요약.
- 지연 가능한 자산: 트리맵 셀과 결과 목록은 검사 뒤 렌더한다.
- 폰트 weight·이미지·영상·모션 예산: 신규 자산·의존성·장식 모션 0.
- 저성능 기기와 느린 네트워크 폴백: 로컬 IPC만 사용하고 reduced-motion에서 전환을 제거한다.

## Accessibility Contract

- 문서·랜드마크·헤딩 읽기 순서: skip link → 전역 내비 → h1 → 하위 내비 → 시작 안내 → 트리맵.
- 키보드·포커스·Escape 동작: 모든 내비와 지도 폴더에 Tab/Enter, 오버레이 Escape, 포커스는 2px 내부 표시.
- 레이블·오류 연결·상태 알림: 입력 label, 단계별 status/error, 진행률 중복 라이브 낭독 금지.
- 대비·색 외 신호·터치 타깃: 14px 이상, 텍스트·아이콘 병행, 주 버튼 44px.
- reduced-motion과 대체 경험: 스크롤·전환 애니메이션 없이도 같은 순서와 상태를 제공한다.

## Adopt

- 기존 macOS처럼 용량 기능을 한 범주와 하위 작업으로 묶는다.
- 면적과 순위로 같은 폴더 크기를 두 방식으로 비교한다.

## Adapt

- 기존 macOS의 기능 수를 그대로 복제하지 않고 현재 Tauri에서 동작하는 4개 작업만 노출한다.
- CLI 연결은 내장 채팅 대신 로컬 연결 상태·권한·등록 안내 화면으로 표현한다.

## Avoid

- 대시보드에 선택 기능 권한을 상시 노출하지 않는다.
- 실제 공급자 프로세스 연결이 없는 채팅 입력창을 만들지 않는다.
- 지도 전에 14개 빈 드라이브 범주를 렌더하지 않는다.

## Prompt Contract

GOAL — 초보 사용자가 폴더 선택부터 용량 원인 확인까지 한 화면에서 진행한다.
AUDIENCE — 디스크 부족 원인을 모르고 앱 사용 순서도 모르는 개인 사용자.
TASK — 폴더 선택, 용량 지도 만들기, 큰 폴더 드릴다운, 상세 검사와 정리 화면 이동.
FLOW — 용량 관리 → 폴더 선택 → 지도 → 큰 파일·중복 → 정리 후보.
HEADER — 쉬운 화면 이름과 한 문장 설명, 관련 화면에서만 폴더 선택을 표시한다.
MESSAGE — 큰 사각형부터 따라가면 용량이 늘어난 위치를 찾을 수 있다.
FACTS — 런타임 경로·크기·수·연결 상태만 표시한다.
CONTENT_INTEGRITY — 자동 AI 연결과 자동 삭제를 암시하지 않는다.
SECTION_ORDER — 하위 탭 → 3단계 안내 → 트리맵 → 결과 이동 → 선택 상세.
CTA — 현재 단계의 다음 행동 하나만 primary.
TRUST — 읽기 전용 검사, 실제 범위, 휴지통 경계를 행동 직전에 설명한다.
ASSETS — 기존 프로젝트 자산만 사용한다.
LAYOUT — 단일 메인 흐름과 단층 표면, 지도 결과만 2분할.
RESPONSIVE — 레일·오버레이 유지, 단계와 지도 순위를 세로 재배치한다.
STATES — loading, empty, error, success, disconnected를 실제 상태에 연결한다.
PERFORMANCE — 신규 의존성·이미지·장식 모션 없이 기존 상한을 유지한다.
ACCESSIBILITY — 14px, 44px CTA, 내부 포커스, 중복 live region 금지.
PRESERVE — 다크 글래스, 실제 검사 엔진, 안전한 휴지통 경계, 트리맵 드릴다운.
EXCLUDE — 첫 화면 CLI 권한, 가짜 채팅창, 중첩 카드, 이중 포커스 링.
SUCCESS — 기본 창에서 다음 행동과 트리맵을 발견하고 최소 창에서도 가로 넘침 없이 완료한다.

## Success Checks

- 첫 5초 안에 핵심 약속과 주 행동을 설명할 수 있는가?
- 화면의 사실·수치·후기·브랜드 자산이 출처와 상태를 가지며, unverified 항목을 사실처럼 보이지 않는가?
- 주요 과업을 막는 상태·정보·행동 누락이 없는가?
- 모바일이 데스크톱 축소판이 아니라 우선순위에 맞게 재구성됐는가?
- 아름다움, 접근성, 성능 중 하나를 다른 하나의 희생으로 얻지 않았는가?
