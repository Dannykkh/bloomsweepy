# 저자원 macOS 검증 기준

## 사용자 의도와 기준 환경

2026-09-07: 사용자는 RAM과 저장 공간이 제한된 현재 맥북에서 최대한 검증하기를 원한다. 이 환경의 제약을 제품 안정성의 핵심 검증 조건으로 취급한다. 고사양 장비에서의 통과로 이 검증을 대체하지 않는다.

- 기준 장비: 현재 Apple Silicon MacBook Air, 물리 RAM 8 GiB.
- 2026-09-07 06:40 KST 관찰: Data 볼륨 약 228 GiB, 사용 약 174 GiB, 사용 가능 약 16 GiB. 여유 공간은 변하므로 매 실행 전후 다시 기록한다.
- 이는 검증 대상 선정이며, 아직 검증을 완료한 최소 지원 사양을 공표하는 것은 아니다.
- 이전 메모리 초과 제보의 종료 앱·직접 원인은 미확정이다. [위험 진단](2026-09-06-memory-risk-audit.md)의 소스 위험과 구분한다.

## 제품 합격 조건

1. 큰 검사에서도 탐색 대기열·파서·SQL 임시 작업·응답의 메모리가 정한 예산 안에 머문다. 결과 표시 개수만 제한하는 것으로 대체하지 않는다.
2. 메모리와 디스크를 함께 제한한다. RAM 임시 작업을 디스크로 옮길 때에도 DB·WAL·임시 파일의 총량과 OS에 남길 여유 공간을 검사한다.
3. 자원이 부족하면 작업을 시작하지 않거나 진행 중인 작업을 안전하게 취소한다. 이유와 검사 완료 범위를 표시하고, 부분 결과를 전체 검사 완료로 표시하지 않는다.
4. 부족·취소·재시도 후 앱이 응답하고, 기존 색인·사용자 파일·작업 이력이 보존된다. 실패한 작업의 임시 자원은 회수하되 사용자 데이터나 복구에 필요한 기록을 임의 삭제하지 않는다.
5. 동일 자료를 반복 처리할 때 완료 후 메모리와 DB/WAL 크기가 계속 우상향하지 않는다. allocator·OS 캐시의 일정한 잔류분과 지속적 증가를 구분한다.
6. 저장 공간 부족 상태에서 검사 완료뿐 아니라 검색·최종 확인·안전한 작업 거부·취소·재시작 후 복구까지 검증한다.

초기 메모리/디스크/시간 예산과 작은 합성 시험 실측은 [안정화 검증 기록](2026-09-07-low-resource-folder-actions.md)에 명시했다. 이는 전체 설치 앱 프로세스 트리·전체 드라이브·장시간 사용의 합격을 공표한 것이 아니다.

## 검증 절차

- 기본 앱 사용량 검증은 빌드가 끝난 설치형 번들로 수행한다. 앱 호스트, WebContent/GPU, 외부 AI CLI, 개발 도구를 분리해 기록한다.
- 공존 부하 검증은 기본 검증 후 별도로 수행한다. 다른 앱의 자원을 임의 회수하거나 종료하지 않는다.
- 작은 합성 자료부터 단계적으로 늘린다. 파일 수·긴 경로·거대한 단일 폴더·느린 소비자·PDF·반복 검사·취소/재시도를 각각 분리한다.
- 작업 전, 작업 중 최고치, 완료 직후, 안정화 후의 프로세스 footprint·시스템 메모리 압박·스왑·여유 디스크·DB/WAL/임시 파일 크기를 기록한다. 전후 RSS만으로 최고 사용량을 검증했다고 하지 않는다.
- 부족 조건은 먼저 낮은 테스트 전용 예산과 디스크-full 오류 주입으로 확인한다. 실제 디스크를 가득 채우거나 시스템 전체 RAM을 고갈시키는 시험은 수행하지 않는다.
- 모든 실제 파일 변경 시험은 테스트 소유 임시 디렉터리로 한정한다. 전체 드라이브 읽기 검증도 안전 한도 구현 후 수행하며 클라우드 제외 정책을 유지한다.
- Windows 동작은 별도 검증한다. 이 맥의 통과를 Windows 완료로 간주하지 않는다.

## 현재 상태
