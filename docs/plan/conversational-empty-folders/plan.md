# 대화형 빈 폴더 관리 — 구현 계약

## 승인과 범위

사용자가 대화형 파일관리 방향 및 `폴더 재검사 → 후보 검토·제외 → 최종 확인 → 휴지통 이동`의 첫 구현 범위를 승인하고 계속 진행을 요청했다. 실제 사용자 파일을 대상으로 개발 검증하지 않는다. 릴리즈·커밋·설치 교체는 이번 범위가 아니다.

## Phase 1 — 조사와 선택

| 대안 | 적합성 | 낮은 위험 | 적은 노력 | 판단 |
|---|---:|---:|---:|---|
| CLI에 파일 도구/쓰기 권한 부여 | 2 | 1 | 4 | 로컬 앱 실행·확인 원칙과 불일치 |
| 키워드로 기존 화면만 열기 | 2 | 4 | 5 | 대화 안에서 후보를 수정할 수 없음 |
| 구조화 요청 + 앱 소유 후보/확인 계획 | 5 | 5 | 3 | 채택: 공급자 공통 경계, 기존 휴지통 기록 재사용 |

암묵 조건: 빈 폴더도 필요한 폴더일 수 있다. 파일 내용은 읽지 않는다. AI는 승인 주체가 아니다. OS 휴지통 API는 경로 기반이어서 다른 프로세스와의 원자적 경쟁 방지를 보장하지 못한다. 실행 직전 재검사로 위험을 줄이고 이 한계를 명시한다.

가장 어려운 결정은 모델에 실행 권한을 주지 않으면서 대화를 이어가는 것이다. 앱 소유 작업 카드를 사용한다. 가장 불확실한 부분은 실제 CLI의 구조화 응답 준수율이며, 잘못된 응답은 작업 없이 실패하도록 한다.

## Phase 3 — 영향도

- core actions/directory: 서버 소유 빈 폴더 신원, 보호 경로 및 비어 있음 재검증. 기존 파일·중복·캐시 검증 유지.
- desktop assistant_tools: 세션 범위, 검사 번호, 익명 후보 번호, 선택 상태, 5분 일회용 확인 계획.
- assistant_provider: 선택형 JSON 응답 계약. 셸/CLI 권한 변경 없음. Docker/이전 호출은 기존 텍스트 응답 유지.
- assistant_sessions: 저장된 세션에서 범위 조회, 최신 폴더 요약 저장. 승인 계획은 재시작 시 소멸.
- trash_actions: 기존 휴지통/기록/취소 파이프라인 재사용.
- AssistantView/bridge/types: 채팅 내부 검토 카드, 선택 수정, 최종 확인, 결과. 세션 전환/진행 중 작업 차단.

## Phase 5 — 공정 점검

소스 흐름, 자동 테스트, 합성 채팅 UI 검증을 완료했다. 완료/실패/취소/만료/중복 실행/후보 교체/알려진 클라우드 경로/숨김 항목을 각 검증 계층에서 확인했다. 상세 범위와 미실행 항목은 [검증 기록](verification.md)에 구분한다.

판정: **소스 구현 완료, 배포 판단은 보류**. 새 프로토콜의 실제 Codex 응답과 네이티브 설치본 통합 검증이 남아 있다. 앞선 계정 사용량 제한 때문에 독립 에이전트 및 CLI 리뷰를 재시도하지 않았으며, 검토 방식은 `sequential-main`이다. 독립 리뷰가 수행됐다고 표시하지 않는다.

후속 사용자 제보: macOS 메모리 초과 종료. 직접 원인은 미확정이지만 공통 탐색 큐·SQLite 임시 작업·PDF 추출의 메모리 예산 보강을 배포 전 우선 점검 항목으로 추가한다. [읽기 전용 메모리 위험 진단](../../qa/2026-09-06-memory-risk-audit.md) 참조.

2026-09-07 사용자 검증 조건: 현재 8 GiB 맥북과 부족한 여유 디스크를 기준 환경으로 사용한다. RAM과 디스크를 동시에 제한하고 부족 시 안전한 중단·재시도를 확인한다. [저자원 합격 기준](../../qa/low-resource-acceptance.md)을 후속 안정화 및 배포 판단에 적용한다.
