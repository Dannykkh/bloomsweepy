# 저자원 안정화와 일반 폴더 휴지통 이동

## 승인·범위

2026-09-07 사용자가 앞서 진단한 문제의 수정을 승인했다. 현재 8 GiB 맥과 약16 GiB 여유 디스크가 기준 환경이다. 기존 미커밋 대화형 빈 폴더 구현을 보존한다. 사용자 파일 삭제·새 릴리스·설치 교체는 수행하지 않는다. 파일 변경 시험은 합성 임시 폴더만 사용한다.

## Phase 1 — 선택과 불확실성

| 대안 | 적합성 | 낮은 위험 | 적은 노력 | 판단 |
|---|---:|---:|---:|---|
| 결과 표시 개수·워커 수만 축소 | 2 | 2 | 5 | 탐색 큐·PDF·SQL 중간 메모리 미해결 |
| 탐색 스트리밍 + RAM/디스크 예산 + 확인 계획 | 5 | 4 | 3 | 채택. 사용자가 승인한 안정화 방향 |
| 별도 검색 서비스와 새 저장소로 전면 재작성 | 3 | 2 | 1 | 검증 범위와 설치 복잡도 과다 |

가장 어려운 결정은 RAM과 디스크의 동시 한도다. 임시 작업을 디스크로 옮기는 것만으로는 부족하므로 캐시·DB/WAL·여유 공간을 함께 제한한다. PDF는 최종 문자열 절단만으로 메모리를 보장할 수 없으며 분리 실행 또는 안전한 제한이 필요하다. OS 경로 기반 폴더 휴지통 호출의 TOCTOU 한계는 남는다. 초기 임계치는 보수적인 정책값이며 전체 환경에 검증된 최적값이라고 주장하지 않는다.

## Phase 3 — 영향도·소유권

- streaming worker: core lib/directory/drive/cleanup/scan_policy 및 새 streaming_walk. 기존 클라우드 제외·빈 폴더 판정·취소·집계 보존. 새 공통 탐색 API를 index worker에 제공.
- index worker: core file_catalog/document_search 및 새 index_budget/PDF worker 지원. 기존 SQL 검색·재색인·취소·이전 색인 보존.
- folder worker: core actions, desktop trash_actions와 폴더 계획 모듈, 공간지도/UI/bridge/types/i18n. 기존 단일 파일·중복·캐시·대화형 빈 폴더 흐름 보존.
- Lead: 공통 모듈/명령 등록 통합, 누락 자원 경계, 검증·문서·활동 장부. 공유 파일 수정은 작업자와 순서를 조율한다.
- 빌드/테스트는 Lead만 실행. 외부 AI CLI 리뷰·대량 부하 테스트·사용자 자료 순회 없음. 네이티브 위임은 workpm 계약에 따라 독립 파일에 한정.

## Phase 5 — 검토

독립 읽기 전용 교차검토에서 발견한 4건(문서 도구 실패 후 기존 색인 소실, 직접 파일 정리의 RAM 검사 누락, OS 자원 고갈의 일반 접근 오류 처리, 선택한 마운트 루트 미차단)을 모두 수정하고 회귀 검증했다. scope는 승인 범위이며 기존 미커밋 대화형 작업은 보존했다. 도면은 항목별 문서 처리, 일반 읽기 오류, 실패 롤백, 소진 후 재검증 순서를 소스에 맞춰 보완했다.

[검증 기록](../../qa/2026-09-07-low-resource-folder-actions.md)에 실제 결과와 잔여 한계를 분리한다. Windows 네이티브 런타임, 실제 Codex 새 대화 계약, 설치 교체·릴리스는 완료로 표시하지 않는다.
