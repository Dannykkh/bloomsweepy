# BroomSweepy Desktop

**대화형 파일관리 시스템 BroomSweepy**의 공용 데스크톱 앱입니다. Tauri 2, React 19, TypeScript, Rust를 사용하며, 대화를 주된 조작 방식으로 삼아 검색·검사·후보 검토·최종 확인·실행 결과를 한 흐름으로 연결하는 것을 목표로 개발합니다.

## 제품 방향과 구현 상태

- 목표 구조: AI는 요청 해석과 앱 도구 선택을 맡고, 실제 파일 작업과 대상 재검증은 Rust 앱이 수행합니다. 채팅의 작업 미리보기·최종 확인·결과 표시를 트리맵 및 파일 목록과 연결하고, AI 공급자별 어댑터가 같은 앱 도구를 사용하도록 합니다.
- v1.7.0 배포본의 빈 폴더 흐름에 더해, 현재 개발본은 일반 파일·내용 있는 폴더의 이름 검색·용량 검사·하위 탐색·삭제 검토를 같은 채팅에서 처리합니다. 기본 휴지통 이동은 인라인 예/아니오 한 번으로 결정하고 직접 입력한 예/아니오도 앱이 처리합니다. 설정의 추가 확인 생략 권한을 켜면 대상을 명확히 이름으로 지정한 제거 요청은 재검증 후 바로 실행합니다. 모델에는 최종 실행 도구를 제공하지 않습니다. 대화형 이름 변경·일반 이동·새 폴더 생성은 미지원입니다.
- 외부 CLI/MCP와 내장 채팅은 서로 다른 호출 경로지만 현재 개발본은 공통 typed 기능 정본과 앱 서비스를 공유합니다. AI는 앱 조회를 선택하고 실제 목록을 분석·추가 조회하며, 최종 파일 작업은 앱의 확인을 거칩니다.

현재 개발본의 내장 채팅은 CLI가 반환한 JSON 작업 요청을 Rust가 처리하고 실제 결과를
모델에 다시 전달합니다. 외부 연결은 MCP를 사용합니다. 두 입구 모두 공통
`file_workspace`로 일반 폴더 검사·큰 항목·이름 검색·하위 탐색·선택·검토·상태 조회를
호출하며, 기존 내장 `files` 요청도 같은 dispatcher의 호환 alias입니다.
외부는 앱 선택 루트만 사용하고 긴 작업은 작업 번호→상태→실제 결과로 이어집니다.
최종 휴지통 이동은 main 앱 확인이며 외부 모델 실행 도구는 없습니다.

MCP 기능 발견은 상한 있는 전체 index와 `capability_details`로 분리해 목록 전체가
잘리는 것을 막습니다. 완료 결과뿐 아니라 진행 중·허용 필요·검토 대기·실패도 분석 전용
응답 한 번으로 설명하며, 후속 AI 오류가 실제 앱 결과나 준비된 검토를 없애지 않습니다.
구현/검증 범위는 [공통 MCP QA](../../docs/qa/2026-10-06-common-mcp-results.md)를 따릅니다.

제품 소개와 현재 사용 가능한 기능은 [한국어 README](../../README.md)와 [English README](../../README.en.md)를 참고하세요.

### 현재 개발본: 정리 후보 트리

기존 정리 후보 탭에서 **폴더 트리**와 **시스템 후보**를 분리합니다. 용량지도 generation, AI 측정 목록의 session/revision 또는 명시적 폴더 검사로 시작하며, 이름 검색만 한 목록은 측정 트리 진입점으로 취급하지 않습니다. 상위 선택은 하위에 상속하고 하위 제외가 있으면 상위 자체를 이동하지 않습니다. 전체/개별 선택, 페이지 이동, 열기·위치 표시, 최종 확인과 실제 작업 결과를 기존 앱 루틴에 연결합니다.

`cleanup_tree.rs`의 단일 workspace는 5분, 16개 가지, 2,048개 노드, 경로 8MiB, 페이지 50개, 실행 대상 100개로 제한합니다. UI는 최대200행입니다. opaque ID·selectionRevision·source generation/revision·루트/노드 신원을 재검증하며, 트리 펼침으로 지도 보고서나 assistant workspace를 교체하지 않습니다. 보호 하위 항목·링크·클라우드·장치 경계의 strict audit은 이 새 트리의 폴더 검토에만 적용하고 기존 폴더/시스템 캐시 정책을 바꾸지 않습니다. 미측정 용량은 null이며 불완전 분기를 추정 삭제하지 않습니다.

검토 계획은 60초 일회용이고, main Webview의 최종 버튼만 기존 OS Trash/저널을 실행합니다. 선택 변경과 화면 이탈은 계획을 무효화하며 다른 검사로 source가 교체되면 재검사해야 합니다. AI 출처의 이동 후에는 무효화된 revision을 반복하지 않고 같은 로컬 루트를 새로 검사합니다. blocking worker가 종료될 때까지 작업 잠금을 유지합니다. 자동 검사·합성 UI와 설치형/OS 실행 검증의 구분은 [트리 QA](../../docs/qa/2026-10-05-cleanup-tree.md)를 참고하세요. 기존 GitHub v1.7.0 배포본에는 포함되지 않습니다.

### 현재 개발본: 일반 파일·폴더 대화 도구

트리의 [후속 macOS 설치 QA](../../docs/qa/2026-10-05-cleanup-tree-native.md)는 새 /Applications 설치본에서 지도/AI 로컬 카드 진입, 선택/제외, 취소, 임시3대상209B 실제 OS Trash, 보존 해시, 재검사와 재실행 기록을 통과했습니다. 외부 모델 요청은0이며 아래 공통 app 조사 루프 전체의 설치형 완료로 확대하지 않습니다. x64 Node와 arm64 Rust가 섞인 환경은 Tauri 패키징 target도 명시해야 합니다. 현재 버전 표시는1.7.0이며 공개 릴리스 파일은 그대로입니다.

현재 개발본은 공통 `app` 요청으로 성능/작업 목록·설치 앱·카탈로그/문서 검색·검사 상태·정리 후보·Docker 조회/검토도 연결합니다. 단일 요청 후 요약으로 끝내지 않고 최대4행동의 실제 앱 결과를 다음 모델 입력으로 전달합니다. 권한·scope·미측정/부분 결과·최종 사용자 확인은 유지합니다. [기능 정본과 역할](../../docs/architecture/app-capability-contract.md), [진행 중 QA](../../docs/qa/2026-10-04-app-tool-integration.md)를 참고하세요. 새 연결의 전체 설치 검증은 아직 완료되지 않았습니다.

`files/largest`는 “가장 큰 폴더/데이터, 삭제해도 돼?”를 읽기 전용 발견으로 처리합니다. 현재 폴더의 직계 항목을 논리 용량순으로 새로 측정하며 폴더는 하위 합계입니다. `sizeRanked`, 측정 시각과 불완전성, 삭제 안전성 미확정 문맥을 제공하되 자동 선택·최종 계획은 만들지 않습니다. 추가 확인 생략을 허용해도 상담·조건부·모호한 요청은 자동 실행하지 않습니다.

일반 scan/largest/browse/parent는 기존 `StoredReports.directory`에 동일 보고서를 한 번 저장하고 작업 공간에는 `mapGeneration`만 남깁니다. `get_assistant_directory_report(sessionId, revision)`은 세션/revision/generation/root를 검사한 뒤 같은 스냅샷을 반환합니다. 화면은 채팅을 이탈하지 않고 지도를 동기화하며 **같은 결과 용량지도 보기**로 열 수 있습니다. 이름 검색만 한 결과는 측정 지도인 것처럼 동기화하지 않습니다. 다른 검사로 보고서가 교체되면 재검사가 필요하며 영구 트리 캐시는 만들지 않습니다.

`assistant_files.rs`는 선택 루트에 갇힌 앱 소유 파일 작업 공간입니다. 공통 typed `file_workspace`와 호환 strict JSON `files` 요청으로 scan/largest/search/review_named/browse/parent/page/select/review/status를 허용합니다. 내장 세션과 외부 workspace는 별개입니다. 로컬 이름 검색은 기존 StreamingWalk, 클라우드/온라인 전용 제외, 메모리 가드를 재사용하고 200개·경로 2 MiB·25만 방문·30초 상한을 둡니다. 모델과 IPC 목록은 24개씩, 검토 선택은 100개, 상태는 16세션으로 제한됩니다. 색인 DB나 본문 전송을 추가하지 않습니다.

고유한 정확한 이름만 자동 검토로 연결하며 검색 누락/접근 실패/동명 항목은 선택 카드로 돌립니다. 검토에서 부모 지도와 항목 신원을 다시 비교하고 기존 파일·폴더 검증기를 재사용합니다. 채팅 파일·빈 폴더·앱 계획은 시간만으로 만료되지 않는 일회용입니다. 선택·revision·inventory·kind 변경과 취소·앱 재시작은 기존 계획을 무효화합니다. `confirm_assistant_file_plan`은 모델 프로토콜에 없으며 main WebView에서 기존 OS Trash/재검증/저널/부분 결과를 실행합니다. 앱 실행 결과만 대화의 완료 사실로 보존합니다.

추가 확인 생략은 기본 OFF이며 기존 Session/Remember 수명을 따릅니다. 명확하게 이름을 지정한 일반 파일·폴더와 Mac 앱 본체 요청만 대상이고, 관련 데이터·프로세스 종료·Docker·영구 삭제는 제외합니다. 복수 계획/불완전 결과는 한 번의 질문으로 돌리고 Rust도 실행 직전 이 권한을 확인합니다. 폴더 트리·지도·시스템 정리의 별도 계획 수명과 확인은 바꾸지 않습니다. [확인 UX QA](../../docs/qa/2026-10-05-conversational-trash-consent.md)

POSIX 폴더 내부 심볼릭 링크는 `symlink_metadata`/`read_link`로 링크 신원·대상 문자열만 fingerprint에 포함하고, 링크 원본을 탐색하거나 용량에 합산하지 않습니다. 링크 수는 최종 카드에 표시합니다. 선택 폴더/부모의 링크·다른 장치·클라우드·오프라인·특수 항목과 Windows 재분석 지점은 계속 거부합니다. 기존 폴더 지도 검토도 같은 검증기를 사용합니다.

실제 Codex의 일반 검사·내용 있는 폴더 검토 요청과 테스트가 만든 16 B 합성 파일/폴더의 실제 macOS Trash 이동을 확인했습니다. Windows 런타임·장시간 자원 검증은 별개로 남아 있습니다. GitHub v1.7.0 다운로드는 기존 배포본입니다.

세부 결과와 설치 검증: [2026-10-04 QA](../../docs/qa/2026-10-04-conversational-files.md). 아래 v1.7.0 절은 공개 릴리스 당시의 범위/검증 기록입니다.

### 개발본: CLI 모델·추론 선택

채팅 입력창은 작은 모델/추론 버튼과 위로 열리는 팝업, 원형 전송 버튼을 사용합니다. 입력창 아래 및 정상 팝업의 반복 설명은 제거하고 오류·미지원·저장값 복구 안내는 유지합니다. 설정의 기존 선택기와 채팅은 같은 공급자·모델별 선호를 공유합니다.

Codex는 설치 CLI 카탈로그(실패 시 내장 목록), Claude Code는 질문 없는 initialize metadata(실패 시 `sonnet`·`opus`·`haiku` 별칭), Grok·Antigravity(agy)는 실제 `models` 출력, Ollama는 로컬 설치 목록을 사용합니다. CLI help에서 모델/추론 옵션을 확인하고 각 모델의 지원 증거만 선택지로 표시합니다. Grok의 미확인 모델이나 Agy 목록에 없는 강도를 추가하지 않습니다. 목록 갱신/업데이트로 저장된 모델을 자동 변경하지 않습니다.

실제 목록이 없으면 CLI 미설치·상태 확인·로그인·서비스·설치 모델 없음·목록 조회 문제를 구분해 안내합니다. 이 Mac의 Grok/Agy는 CLI가 설치되지 않았습니다. 이때 모델 팝업/설정에 공식 문서의 참고 모델만 읽기 전용으로 보여 주며, 참고 항목은 실제 선택·선호·추론 단계에 넣지 않습니다. 실제 CLI 목록이 생기면 참고 목록은 숨깁니다. 참고 예시는 최신/전체/계정별 실행 가능 목록을 보장하지 않습니다. [Grok 설치 안내](https://docs.x.ai/build/overview) · [Agy 설치 안내](https://antigravity.google/docs/cli/install/)

기본값은 모델/강도 인자를 생략합니다. 명시 선택은 Codex의 `--model`·`--config model_reasoning_effort=…`, Claude/Grok/Agy의 `--model`·`--effort`에 반영합니다. version1의 공급자·모델별 선호와 stale 값 전송 차단, 기존 응답 제한/취소·앱 기능·권한 계약을 유지합니다. 모델 옵션만 미지원인 CLI는 기존 기본값 경로를 유지하며, 모델/강도 거부 시 자동 fallback하지 않습니다. 계정별 모델 접근권과 서버의 실제 강도 적용은 선택 목록이나 응답의 요청값 표시만으로 확정하지 않습니다.

이 Mac의 Claude Code2.1.291 metadata-only 조회와 compact fixture 관찰은 확인했으며, Grok/Agy는 CLI 미설치로 실제 실행을 검증하지 않았습니다. 이번 통합/최종 설치 검증 상태는 [다중 공급자 QA](../../docs/qa/2026-10-07-multi-provider-model-selection.md), 세부 동작은 [모델 계약](../../docs/architecture/assistant-model-selection.md)을 따릅니다. 이전 Codex 설치 검증은 [추론 QA](../../docs/qa/2026-10-06-cli-reasoning-selection.md)에 별도로 기록되어 있습니다. 현재 개발본과 공개 v1.7.0은 구분합니다.

Claude 모델은 CLI `resolvedModel`의 버전을 포함해 표시합니다. 같은 질문 없는 초기화에서 최신 `fable` alias도 확인하므로 Fable 5와 Fable 5.1을 구분할 수 있습니다. 버전 이름을 고정 매핑하거나 실행 ID·기존 모델 선호를 바꾸지 않습니다. 목록의 버전은 현재 alias 해석이며 과거 응답의 실제 모델 버전으로 소급하지 않습니다.

### v1.7.0: 대화형 빈 폴더 정리

`assistant_tools.rs`의 공통 JSON 요청은 세션의 폴더 재검사·24개 후보 페이지·후보 선택 수정만 허용합니다. AI는 경로나 셸 명령을 전달하거나 최종 승인·휴지통 이동을 호출할 수 없습니다. 채팅 안의 카드가 최대 200개 후보의 실제 경로를 보여주고, 사용자 선택에 묶인 5분 일회용 계획을 별도 확인 버튼으로 실행합니다. 기존 휴지통 기록·취소·부분 실패 경로를 재사용하며, 비어 있음·신원·보호 경로·클라우드·링크를 재검증합니다. 실제 Codex와 새 도구 흐름의 종단 검증은 남아 있으며 자세한 범위는 릴리스 안내를 참고하세요.

검사와 후보 관리는 로컬이며, AI 입력은 제한된 요약·후보 이름/번호·질문·대화 기록입니다. 파일 본문이나 후보 전체 경로를 자동 첨부하지 않습니다. 사용자 입력이나 별도 MCP 검색에는 경로·본문이 포함될 수 있고, CLI 읽기 전용은 외부 전송 차단이 아닙니다. 토큰 효율은 전달 데이터와 호출 횟수에 달렸으며 절감률은 미측정입니다.

### v1.7.0: 저자원 보호·일반 폴더 이동

현재 소스는 탐색 대기열 대신 제한된 스트리밍 탐색을 사용합니다. 호스트 작업 메모리 512 MiB와 시스템 여유 RAM 256 MiB를 500ms 간격으로 확인하며, SQLite 캐시·DB/WAL·여유 디스크에도 별도 예산을 둡니다. PDF·Office 문서는 128 MiB Rust 할당 예산과 15초 제한을 가진 별도 프로세스에서 처리합니다. 처리 도구나 자원 문제로 실패한 재색인은 이전 완료 색인을 보존합니다. 이는 전체 앱 프로세스 트리의 OS 하드쿼터가 아닙니다.

용량 지도에서 폴더의 **더보기 → 휴지통 이동 검토**를 선택하면 전체 경로·파일/폴더 수·논리 용량을 확인할 수 있습니다. 하위 항목 전체 이동에 체크한 뒤 최종 버튼을 눌러야 실행하며, 계획은 5분 동안 한 번만 사용합니다. 검사 루트·다른 장치·시스템·클라우드·링크 경계는 차단합니다. 일반 폴더 내부의 숨김 파일·앱·프로젝트도 함께 이동하므로 반드시 검토하세요. 영구 삭제나 자동 휴지통 비우기는 하지 않습니다.

정책값·검증 범위·남은 제한은 [v1.7.0 릴리스 안내](../../docs/releases/v1.7.0.md)를 참고하세요. v1.6.1 공개 릴리스에는 이 기능이 없습니다.

### v1.7.0: macOS 메뉴 막대

`src-tauri/src/menu_bar/macos.rs`가 Rust/objc2로 네이티브 상태 아이콘과 재사용하는 NSPopover 하나를 관리합니다. CPU·RAM 집계와 `/`의 statvfs만 10초마다 읽고, 프로세스 목록·파일 순회·추가 WebView·측정 이력은 생성하지 않습니다. 샘플러 하나와 최신 측정값 하나만 유지하고 메인 스레드 UI 갱신도 최대 한 건만 대기시킵니다. 종료 신호 또는 채널 해제 시 측정을 중단합니다.

창 닫기는 숨김, 패널의 열기와 Dock 클릭은 기존 창 복원, 종료/⌘Q는 기존 작업 종료 절차를 사용합니다. 아이콘 생성에 실패하면 창 닫기 동작을 가로채지 않습니다. 숫자 표시 설정은 NSUserDefaults에 저장하고 패널·설정 화면을 이벤트로 동기화합니다. 메인 창을 숨겨도 기존 상태/메모리는 유지됩니다. macOS 전용 코드이며 Windows 트레이는 그대로입니다.

## 명령

```powershell
npm install
npm run check
npm run test:all
npm run build
npm run prepare:sidecar
npm run tauri dev
npm run tauri build
```

Rust 워크스페이스 명령은 저장소 루트에서 실행합니다.

```powershell
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

`prepare:sidecar`는 MCP와 문서 처리 도구를 모두 준비합니다. 8 GiB 환경에서는 Cargo 실행 시 `CARGO_BUILD_JOBS=1 CARGO_INCREMENTAL=0`으로 빌드 작업을 직렬화할 수 있습니다. 새 문서 도구 없이 배포하면 PDF·Office 재색인이 안전 오류로 중단됩니다.

## 안전 경계

- 일반 파일 작업은 검증된 후보의 운영체제 휴지통 이동입니다. 별도 시스템 휴지통 비우기와 Docker 정리만 명시적 영구 삭제 예외입니다. AI/CLI/MCP에는 휴지통 비우기 권한을 주지 않습니다.
- 문서 본문 색인은 로컬 앱 캐시에 저장합니다. 별도 허용한 MCP 문서 검색은 경로와 일치 문맥을 외부 클라이언트에 반환할 수 있습니다.
- 문서 색인은 공유 읽기 핸들·크기 상한·취소 가능한 트랜잭션을 사용하고 마지막 완료 색인을 보존합니다.
- 빠른 파일 찾기는 본문을 열지 않고 이름·경로·크기·수정 시각만 앱 캐시에 색인합니다.
- 파일 카탈로그도 취소 가능한 트랜잭션과 공용 단일 작업 잠금을 사용하며, 앱의 휴지통 이동 뒤에는 업데이트 전까지 검색을 잠급니다.
- 트리맵 분석·드릴다운과 빈 폴더 탐색은 읽기 전용입니다. 별도 더보기 메뉴의 개별 파일 휴지통 이동에는 파일 신원·경로 재검증과 최종 확인을 적용합니다.
- 알려진 클라우드 동기화 경로와 온라인 전용 항목은 순회 전에 제외하며, 인식된 클라우드 루트의 직접 검사도 거부합니다.
- macOS 앱 메모리 정리는 BroomSweepy 호스트 프로세스의 미사용 allocator 페이지만 반환하며 시스템 전체·다른 앱·WebView 보조 프로세스의 메모리는 건드리지 않습니다.
- 부분 해시는 후보 축소에만 사용합니다.
- 중복 결과는 전체 BLAKE3 해시와 바이트 비교까지 통과해야 합니다.
- 하드링크는 동일한 디스크 할당으로 계산해 회수 가능 용량에서 제외합니다.
- 중복 사진 필터도 바이트가 완전히 같은 파일만 포함하며 유사 사진으로 확대 해석하지 않습니다.
- 파일 더블클릭은 실행 파일과 스크립트를 실행하지 않고 탐색기에서 위치만 표시합니다.
- Temp는 7일, AppData는 90일의 변경 없음 근거를 요구하며 AppData는 항상 검토 대상으로 표시합니다.
- 제거 프로그램 레지스트리는 서로 다른 경로 증거가 둘 이상 끊긴 항목만 검토 대상으로 표시하고 변경하지 않습니다.
- 휴지통 이동은 서버 보고서 재검증, 그룹별 보관본, 작업 저널, 부분 실패 중단을 강제합니다.
- 앱 내부 자동 복원은 제공하지 않습니다. 일반 이동은 OS 휴지통에서 복원하며, 별도 휴지통 비우기를 실행하면 복원 수단이 사라집니다.

## 문서용 화면 재현

`npm run dev` 후 `http://127.0.0.1:1420/release-preview.html?view=dashboard&language=ko`를 엽니다.
`view`는 `dashboard`, `overview`, `performance`, `assistant`, `settings`를 지원하며 `language`는 `en`, `ko`, `ja`, `zh-CN`입니다.
실제 React 화면에 예시 데이터를 공급하는 개발 전용 진입점으로, 패키징된 앱에 포함되지 않으며 실제 파일·AI·OS 작업은 실행하지 않습니다.
캡처 규격은 [스크린샷 안내](../../docs/assets/screenshots/README.md)를 참고하세요.
