BroomSweepyは、WindowsとmacOS向けのストレージ分析・クリーンアップ確認ツールです。大容量ファイル、内容まで検証した重複ファイル、空フォルダ、クリーンアップ候補、ファイル名、対応文書内の文章を検索できます。実際のスキャンはローカルのRustエンジンが行い、AI接続は任意です。

言語ごとに別のインストーラーを使う必要はありません。初回起動時は英語で表示されます。`Settings > Display language`でEnglish・한국어・日本語・简体中文を選ぶと、アプリ画面、Windowsのトレイメニュー、AIへの応答言語指定がすぐに切り替わり、このコンピューターだけに保存されます。

## 基本的な使い方

1. `ストレージ`を開き、確認するフォルダを選びます。
2. `ストレージマップを作成`を選びます。大きい長方形ほど多くの容量を使用しており、フォルダの長方形を選ぶと下の階層へ移動できます。
3. 詳細が必要な場合だけ`大容量ファイルと重複を検索`を実行します。ファイル内容を読むのは重複候補の比較時だけです。
4. 移動対象を自分で選び、最終確認してからOSのゴミ箱へ移動します。

名前や場所で探す場合は`ファイル検索`、文章で探す場合は`ドキュメント検索`を使用します。これらの基本機能にAI、CLI、MCP接続は必要ありません。

## 主な機能

- ドライブ使用量、空き容量、最近のゴミ箱操作、最近追加されたファイルをまとめるダッシュボード。
- フォルダをたどれる比例長方形の`ストレージツリーマップ`。
- サイズ分類、部分BLAKE3、全体BLAKE3、最終バイト比較による重複確認。
- ファイル名・パスと対応文書の本文を高速検索するローカルSQLite FTSインデックス。
- TXT、Markdown、ソースコード、PDFのテキスト層、DOCX、XLSX、PPTX、HWPXの索引作成。
- Windowsの読み取り専用レジストリ情報とmacOSの`.app/Contents/Info.plist`を利用したアプリ一覧。
- Temp、キャッシュ、AppData、アンインストール後の残存候補を自動削除せず確認できる画面。
- バックグラウンドスキャン、メモリ・結果件数の上限、キャンセル地点、実行直前の再検証。
- OSのゴミ箱移動、同期JSONLジャーナル、中断した操作の確認。
- 任意で有効にするDocker専用画面。Dockerボリュームは削除対象にしません。
- 開発ブランチ（リリース前検証中）：利用者が明示的に切り替えるWindows・macOSのログイン時起動と、総容量・使用可能・使用中・`sysinfo`が報告するスワップ指標だけを読むシステムメモリ表示。Windowsのスワップ値はコミット量ベースの推定であり、ページファイルの現在使用量ではありません。キャッシュの削除やメモリリークの解消は行いません。

## AI・CLI・MCPの境界

スキャン、索引作成、再検証、ゴミ箱への移動は、このコンピューター上のBroomSweepyが行います。Codex、Claude Code、Grok、Antigravity、Ollamaは上限付きの結果を要約して確認対象を提案できますが、アプリから無制限のファイルシステム操作権限は渡しません。

MCPのクリーンアップツールが扱うのは匿名の候補番号と制限された要約だけです。承認、完全削除、ゴミ箱移動の実行、レジストリ書き込み、ゴミ箱を空にするツールはありません。正確なパスはアプリ内だけで表示し、利用者がそこで確認した場合に限って処理します。

## Dockerは任意機能です

Docker機能は初期状態で無効です。無効中はDocker CLIの検索も実行もしません。有効にすると、専用画面で`docker system df`の結果を確認し、古いビルドキャッシュ、未参照イメージ、停止中コンテナに限定した固定コマンドだけをプレビューできます。DockerクリーンアップはOSのゴミ箱を経由しないため、別の復元不可確認が必要です。

## 対応環境と開発

Windows用インストーラーはWindowsで作成します。署名・公証済みの`.dmg`はmacOS上で作成する必要があります。

必要な環境はRust stable、Node.js 22以降、npm、およびWindowsではWebView2とMSVC Build Toolsです。

```powershell
cd apps/desktop
npm install
npm run tauri dev
```

詳細な実装・安全設計は、[韓国語の詳細README](README.md)、[CLI制御](docs/cli-control.md)、[クロスプラットフォーム構成](docs/architecture/cross-platform-desktop.md)、[自動起動とシステムメモリ状態](docs/architecture/startup-memory-status.md)、[安全なゴミ箱操作](docs/architecture/safe-trash-actions.md)を参照してください。

## 重要：データ損失と復元に関する責任

BroomSweepyは、利用者が選択して最終確認した項目だけを処理するよう設計されています。ただし、復元の可否はOS権限、ゴミ箱設定、同期サービス、外付け・ネットワークドライブの状態に左右されます。DockerクリーンアップはOSのゴミ箱を使用せず、完了した処理は元に戻せません。

実行前に重要なデータをバックアップし、選択したパス、ファイル、Docker分類を必ず確認してください。法律上免責できない場合を除き、利用者が実行したファイル移動・削除・ゴミ箱を空にする操作・Dockerクリーンアップによるデータ損失や復元失敗について、プロジェクト提供者および貢献者は責任を負いません。
