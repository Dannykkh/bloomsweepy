BroomSweepyは、WindowsとmacOS向けの**対話型ファイル管理システム**を開発するプロジェクトです。会話を主な操作方法として、ファイル検索からスキャン、候補の検討、条件の調整、最終確認、実行結果の確認までを一つの流れで進められる体験を目指しています。

**Rust + Tauri 2 + Reactがメインプロジェクト**となり、従来のSwiftUIアプリの広々としたカード、分かりやすいアイコン、ガラス調のUIを受け継ぎます。`BroomSweepy/`のSwiftソースは従来版の参考実装です。大容量ファイル、内容を検証した重複ファイル、文書検索はローカルのRustエンジンで処理し、既存の閲覧・スキャン画面はAI接続なしでも利用できます。1つのアプリで英語・韓国語・日本語・簡体字中国語に対応し、初回は英語で表示します。`Settings > Display language`で変更できます。

## v1.8.0 — 会話によるファイル・フォルダ管理

内蔵チャットのゴミ箱移動は別の確認ポップアップを挟まず、**はい・いいえの1回**で決めます。待ち時間だけでは確認を失効させません。入力欄の**権限選択**、または**設定 → AI・権限 → 接続と権限 → チャット権限**から、`閲覧のみ`・`確認してから実行`（初期値）・`フルアクセス`を選びます。閲覧のみでは変更の準備も実行もしません。フルアクセスを明示的に選ぶと、`promo-videoを削除して`のように全対象名を指定した、単純で直接的なファイル・フォルダ・アプリ本体の削除命令は再検証後に処理します。条件付き・相談・引用・複合文や未対応の表現は、はい・いいえで確認します。「削除してもいい？」、曖昧な対象、関連データ、プロセス終了、Docker整理、完全削除はこの自動実行権限の対象外です。設定の選択は既存の権限保持方法に従いますが、個別の計画・承認は保存しません。MCPやモデルに実行ツールを追加するものではありません。[確認フローQA](docs/qa/2026-10-05-conversational-trash-consent.md)

フルアクセスではフォルダの会話を開いてから、**ローカルドライブ一覧**や会話でローカルボリュームを参照し、全体の名前検索で見つけた正確な対象を既存のファイル管理カードで開けます。検索には時間・件数・メモリの上限があり、クラウド・ネットワークの場所や別のマウント先をたどりません。読み取れない項目や制限に達した結果は部分結果として示し、自動のゴミ箱移動には使いません。このモードはmacOSのフルディスクアクセス、文書本文の公開、外部MCP権限、完全削除の権限を付与しません。従来の確認省略設定をフルアクセスへ自動移行することもありません。[権限モードの検証](docs/qa/2026-10-11-chat-access.md)

会話画面は中央の履歴と、常に表示する下部入力欄で構成します。CLI準備・応答待ち・アプリへの問い合わせ・結果分析の段階と経過時間を表示し、応答を中断できます。取得一覧はその回答に付けて折りたたみ、最終確認・失敗・権限不足は初期状態で開きます。ただし画面に戻ると以前のファイル結果が最新回答の下に現れる既知の問題があり、出典表示の改善が必要です。完了した確認は処理要約として残し、失敗も会話に表示して、該当の質問を明示的に再試行できます。接続と権限は設定と会話対象の横のボタンで確認します。トークンのストリーミングや推定進捗率の表示ではありません。v1.8.0のUIであり、既存のv1.7.0配布ファイルは変わりません。[チャット検証記録](docs/qa/2026-10-05-chat-workbench.md) · [応答・カードの寿命の検証](docs/qa/2026-10-11-chat-response-timeline.md)

**整理候補 → フォルダツリー**で下位フォルダを展開し、全体または個別に選択できます。親の選択は配下にも適用されますが、子を外した場合は親フォルダ自体を移動しません。容量マップやAIの測定済み一覧から同じ検査結果を開き、最終確認後にゴミ箱へ移動します。この新しいページでは隠れた保護項目・リンク・クラウド・別デバイスを厳密に検査します。状態は最大2,048ノード、表示は200行に制限し、未測定・部分結果・期限切れを明示します。2026-10-05、表示バージョン1.7.0のMac開発版で一時資料3対象209Bの移動、子ファイル保持・キャンセル・再検査・AIローカルカードからの移動・再起動後の履歴を検証しました。Windows・外部モデルの調査全体・長時間メモリ検証は未実施です。[ツリー検証記録](docs/qa/2026-10-05-cleanup-tree.md) · [Mac実機検証](docs/qa/2026-10-05-cleanup-tree-native.md)

「ここで最も容量の大きいフォルダやデータは？削除してもいい？」と聞くと、現在のフォルダ直下の項目を新しく測定し容量順に表示します。フォルダの容量は配下の合計で、容量だけでは削除の安全性を判断できません。**同じ結果を容量マップで見る**で同じ検査をツリーマップに再利用します。名前だけで見つけたフォルダは内容を検査するまで未測定です。部分結果、読み取り失敗、期限切れを区別し、この質問だけでは削除対象の選択や削除を行いません。

AIに検査、名前検索、`promo-video`などのフォルダ整理を依頼すると、Rustアプリが検索・容量計算・下位探索・ゴミ箱移動の確認を行います。空でないフォルダも対象です。同じ会話のカードで開く・場所の表示・選択変更・最終確認・項目別結果を扱います。AIに任意の削除権限を渡すのではなく、アプリの検証済みゴミ箱ルーチンを利用します。

名前検索は最大200件、AIと画面は24件ずつ、移動確認は最大100件です。未検査のフォルダ容量は未測定と表示します。同名項目や不完全な検索から対象を自動選択しません。フルパス・内容・論理サイズを示し、基本のはい・いいえの質問ではフォルダ配下の内容も一緒に移動することを案内します。チャットの計画に時間制限はなく、1回限り使用でき、選択変更・再検査・再起動で無効になります。実行直前に変更・リンク・クラウド・保護パスを再検証します。完全削除、任意シェル、会話での名前変更・通常の移動・フォルダ作成は提供しません。

v1.8.0の対象ソースに含まれる追加機能で、既存GitHub v1.7.0の配布物には含まれません。実際のCodexの検査/空でないフォルダ確認要求と、合成項目のmacOSゴミ箱移動は、表示1.7.0の開発版で検証した履歴です。Windows実機と長時間の資源検証は未実施です。

macOSでは実フォルダ内部の`node_modules/.bin`などのシンボリックリンクはリンク自体のみ移動し、リンク先をたどりません。確認カードに件数を表示し、リンク先の変更も再検査します。選択対象/親のリンク、クラウド・別デバイス・特殊項目の保護は維持し、Windowsの再解析ポイント/ジャンクションは引き続き拒否します。[開発版検証記録](docs/qa/2026-10-04-conversational-files.md)

### 対話型空フォルダ整理の使い方

1. AIアシスタントでローカルフォルダを選び、空フォルダの検査を依頼します。
2. 再検査した候補カードを確認し、会話またはチェックボックスで残すフォルダを除外します。
3. 正確なパスと選択内容を確認し、**最終確認ボタン**でゴミ箱移動を実行します。
4. 項目別の成功・失敗・スキップを確認します。

候補は最大200件、AIに渡す1ページは最大24件です。保護・変更・上限による除外数を表示します。計画は5分間有効な使い切りで、選択変更・再検査・再起動により無効になります。会話やAIの返答だけでは実行しません。一般ファイルの移動・名前変更を会話で行う機能は未対応です。**実際のCodex CLIを使った新ツールのエンドツーエンド検証は未完了です。**

### アプリ管理とファイルを開く操作

`アプリ管理`で全ドライブの検査なしに一覧を表示します。Macは専用アンインストーラを優先し、通常のアプリ本体のみ個別確認後にゴミ箱へ移動します。関連データは正確なアプリ識別子に一致するキャッシュと環境設定だけを別途選択・確認します。書類、Application Support、Containers、共有データは自動候補から除外します。Windowsは正式な「インストールされているアプリ」の削除画面を開き、アプリフォルダ・レジストリ・AppDataの推測削除は行いません。画面が開いても削除完了を意味しません。

「開く」は通常の書類・メディアを既定のアプリで、通常のフォルダをファイルマネージャで開きます。実行ファイル・スクリプト・アプリパッケージは実行せず場所を表示します。場所の表示とアプリ内の下位フォルダ探索は別の操作です。AI・CLI・MCPへの削除権限追加はありません。

### ローカル処理・トークン・送信範囲

検索・検査・集計・候補管理は手元のコンピューターで行い、AIには上限付きの要約を渡します。ローカルのファイル操作自体はLLMトークンを使いません。節約の要因はRustではなく、全ファイル一覧の代わりに必要な要約を送ることです。適切に構成した一般CLIでも同程度の効率が得られます。同じ作業を完了する条件での削減率は未測定です。

クラウドAIには名前・サイズ・件数・候補番号と質問・会話履歴が送信されます。アプリのフォルダ要約と新しい候補ページに本文・フルパスは自動挿入しませんが、直接入力したパスや内容は質問・履歴に含まれ得ます。ローカルCLIや読み取り専用権限は、完全オフラインや外部送信の完全防止を意味しません。別途許可したMCPファイル・文書検索ではパスや一致箇所が返る場合があります。外部送信ゼロや一定のトークン削減率は保証しません。

### リソースの範囲と検証の制限

本体メモリ512 MiB超過、またはシステム空きRAM256 MiB未満で重い処理を協調的に中断します。PDF・Office処理はRust割り当て128 MiBと15秒の制限を使用し、索引更新に失敗した場合は前回完了した索引を保持します。アプリ全体・WebView・CLIに対するOSのハード上限でも、メモリリーク解消の保証でもありません。ウインドウを隠しても状態とメモリは保持します。

- ローカル自動検査：Rust273件・フロントエンド43件成功。任意の実CLI診断1件は未実行。
- 未検証：新しいCodexツール連携、長時間の全プロセスメモリ安定性、実際のユーザーアプリ削除・ゴミ箱の完全消去。
- メニューバー設定の保存・再起動・完全終了は確認済み。アイコンの直接クリック、パネル内操作、キーボードの視覚検証は残っています。
- アプリ全体の容量・インストール日・名前/日付/容量による並べ替え選択は未対応。部分一致検索は利用できます。
- Windowsのインストーラーと自動検査はCIで実行します。CI成功は実際のインストール・GUI・ゴミ箱操作の検証を意味しません。

## 安全性とクラウドの除外

スキャンはファイルを変更しません。大容量・重複検査、ドライブ集計、ツリーマップ、ファイル一覧、文書索引は既知のクラウド同期ルートとオンライン専用項目を除外します。macOSの`~/Library/CloudStorage`、`~/Library/Mobile Documents`と認識済みのGoogle Drive・iCloud・OneDrive・Dropboxパスは走査前に除外し、直接選択しても検査しません。認識済みルート内のダウンロード済みファイルも除外します。任意の場所へ移動した同期フォルダや、すべてのプロバイダーの自動識別は保証しません。

重複はサイズ、部分・全体BLAKE3、最終バイト比較で検証します。ファイル移動は選択、再検証、最終確認、記録を経てOSのゴミ箱を利用します。v1.7.0の空フォルダ移動は最終確認が必要です。以下のゴミ箱を空にする操作は、個別確認を伴う完全削除の例外です。移動した論理サイズは増えた空き容量と同じではありません。レジストリの自動削除は提供しません。

v1.7.0では、ストレージ画面上部に「ゴミ箱を開く」と「システムのゴミ箱を空にする」を追加しました。後者は、接続されたドライブにある現在のユーザーのゴミ箱全体をOSに空にするよう要求します。他のアプリで捨てた項目も含まれ、選択フォルダには限定されません。警告、確認チェックボックス、2分間有効な使い切り確認を別途必要とします。AI/CLI/MCPには公開せず、ゴミ箱全体の事前スキャンや空き容量の保証もしません。Macのローカルインストール版で警告画面とキャンセルを確認しました。実際にゴミ箱を空にする操作は未実施です。

メモリ整理はシステム全体、他のアプリ、WebView補助プロセス、スワップ、メモリリークを解消しません。CPU整理機能はありません。macOSの通常終了要求は別の確認操作で、強制終了には切り替えません。Windowsのパフォーマンスは読み取り専用で、スワップはページファイルの現在使用量ではなくコミット量ベースの推定値です。

Docker管理は初期状態で無効です。有効時も固定コマンドだけを使い、ボリュームを除外し、復元不可の操作として別途確認します。

## AI・CLI・MCP

v1.8.0では、**チャット入力欄の`[CLI選択] [モデル・推論強度]`**または**設定 → AI・権限 → AIモデル**から同じ選択を管理します。最初のボタンでCodex・Claude Code・AGY・Grok・Ollamaを切り替えると、そのCLIのモデルとモデルごとの強度の選択が復元されます。Codex・Claude Code・Grok・AntigravityではCLIが提供する実際のモデル一覧と対応強度を使い、Ollamaではインストール済みモデルを選びます。非対応の推論段階は作りません。選択はこのコンピューターに保存しますが、CLI全体の設定・ログイン・削除権限は変更しません。一覧はアカウントごとの利用権限を保証せず、モデルエラー時に自動で切り替えません。CLIが未導入の場合はインストールが必要な状態を示し、質問を送信できません。既存のv1.7.0配布ファイルは変わりません。[モデル選択の契約](docs/architecture/assistant-model-selection.md)

v1.8.0の対象ソースでは、LLMがアプリのパフォーマンス・インストール済みアプリ・検索・検査・整理候補の参照を選び、アプリが返した実際の一覧を分析して必要な追加参照を依頼します。内蔵チャットはCLIの構造化された要求（JSON）をアプリ共通のdispatcherへ渡し、外部MCP通信そのものは経由しません。外部MCPも同じ[共通機能の正本](docs/architecture/app-capability-contract.md)とアプリエンジンを使います。変更は権限モード・対象の再検証・操作別の確認規則に従います。表示1.7.0のMac開発版では実際のCodex連携とインストール済みsidecarの読み取り専用stdio検証がそれぞれ成功しましたが、v1.8.0配布版や全機能・全プロバイダーのエンドツーエンド検証を完了したという意味ではありません。[実際の検証と制限](docs/qa/2026-10-21-installed-chat-audit.md)

Codexデスクトップアプリを入れただけでは、Codex CLIが導入されているとは限りません。利用するCLIの導入、互換バージョン、ログイン状態をアプリで確認してください。Mac開発版で行った実測の履歴は上の状態表を参照してください。Claude Code・Grok・Antigravity・Ollamaのアダプターもありますが、すべての実動作を検証したわけではありません。公開v1.7.0当時の未検証項目は、そのリリースの節に別途残しています。

アプリ内チャットは項目名とサイズを含む上限付きのフォルダ要約、質問、会話履歴を選択したプロバイダーへ送ります。ローカルCLIでもモデル処理がオフラインとは限りません。MCP整理ツールは匿名候補IDと制限付き要約を提供し、承認・削除実行ツールは持ちません。ファイル・文書検索を別途許可すると、パスや一致部分が外部クライアントへ渡る場合があります。実際のファイル操作はアプリの権限・再検証・確認規則に従います。

フォルダ検査は別の許可スイッチなしで、アプリでフォルダを選べば使えます。外部MCPの検査要求もその選択フォルダとアプリの検査基準だけで実行し、任意のパスは受け取りません。フォルダを変えると従来の外部検査範囲を先に解除して、新しい範囲を接続します。アプリ自身のフォルダ検査は外部AI接続なしでも使えます。削除・アプリ削除・プロセス終了の最終確認は別の規則です。

v1.8.0の**設定 → AI・権限 → 接続と権限 → 権限の保持方法**で、`今回の実行のみ`（初期値）または`このコンピュータに保存`を選べます。保存するのは、ユーザーが許可したシステム・アプリ参照、検索フォルダ、アプリで選択した検査フォルダと基準、整理計画の確認許可だけです。保持方法を変えるだけで無効な公開権限が自動的に有効になることはありません。選択フォルダや検査基準の変更は直ちに範囲へ反映し、消えたフォルダや対象の変わったリンクは再起動時に復元しません。`今回の実行のみ`へ戻すと保存済みの範囲・許可を消しますが、現在の実行では完全終了するまで維持します。ウインドウを閉じてもメニューバーに常駐する場合があり、完全終了とは異なります。削除・アプリ削除などの最終確認と整理計画は保存しません。既存のv1.7.0配布ファイルは変わりません。
