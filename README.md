BroomSweepy는 Windows와 macOS용 **대화형 파일관리 시스템**을 만드는 프로젝트입니다. 대화를 주된 조작 방식으로 삼아, 파일 검색부터 검사·후보 검토·조건 조정·최종 확인·작업 결과 확인까지 한 흐름으로 이어가는 경험을 목표로 개발합니다.

**Rust + Tauri 2 + React가 기본 프로젝트**이며, 기존 SwiftUI 앱의 시원한 카드·아이콘·글래스 UI 경험을 이어갑니다. `BroomSweepy/`의 Swift 소스는 레거시 참고 구현입니다. 큰 파일·검증된 중복 파일·문서 검색은 로컬 Rust 엔진으로 동작하며, 기존 탐색·검사 화면은 AI 연결 없이도 사용할 수 있습니다. 하나의 설치본에서 English·한국어·日本語·简体中文을 지원하며, 첫 실행 언어는 영어입니다. `Settings > Display language`에서 바꿀 수 있습니다.

## v1.7.0 — 대화형 파일관리와 저자원 보호

[정식 릴리스와 설치 파일](https://github.com/Dannykkh/bloomsweepy/releases/tag/v1.7.0) · [변경 기록](CHANGELOG.md)

- **대화형 빈 폴더 정리**: 앱의 로컬 재검사, 후보 카드, 대화로 제외 조건 조정, 최종 확인, 항목별 결과를 연결했습니다.
- **폴더 정리와 열기**: 용량 지도에서 일반 폴더 전체의 휴지통 이동을 별도로 검토하고, 파일·폴더 열기와 위치 표시를 구분합니다.
- **앱 관리**: 설치된 앱 목록과 이름·제작사·경로의 포함 단어 검색. Mac 앱 본체와 관련 데이터는 따로 검토하고, Windows는 운영체제 제거 화면으로 연결합니다.
- **운영체제 휴지통 비우기**: 사용자 휴지통 전체를 대상으로 하는 별도 영구 삭제 확인입니다. AI에는 이 권한을 주지 않습니다.
- **저자원 보호**: 제한된 스트리밍 탐색, 색인 메모리·디스크 예산, 별도 문서 처리 프로세스를 추가했습니다.
- **macOS 메뉴 막대**: 네이티브 패널로 RAM·CPU·시스템 디스크를 10초마다 표시합니다. 숫자 표시 설정을 저장하고, 창 닫기는 숨김·열기는 복원·종료/⌘Q는 완전 종료로 구분합니다. 별도 WebView는 만들지 않습니다.

메뉴는 **대시보드 → 성능 → 앱 관리 → 공간 정리 → 파일 관리 → AI 도우미 → 설정** 순서입니다. Docker 관리는 기본 꺼짐이며 사용자가 켠 경우에만 나타납니다.

### 대화형 빈 폴더 정리 사용법

1. AI 도우미에서 검사할 로컬 폴더를 선택하고 “빈 폴더를 검사해 줘”라고 요청합니다.
2. 앱이 재검사한 후보 카드를 확인하고, 대화나 체크박스로 남겨둘 폴더를 제외합니다.
3. 정확한 경로와 선택 내용을 최종 검토한 뒤 **확인 버튼**으로 휴지통 이동을 실행합니다.
4. 항목별 성공·실패·건너뜀 결과를 확인합니다.

검토 후보는 최대 200개, AI 후보 페이지는 최대 24개입니다. 보호·변경·상한 때문에 빠진 항목 수를 표시합니다. 확인 계획은 5분간 한 번만 유효하며 선택 변경·재검사·재시작으로 무효화됩니다. “삭제해”라는 대화나 AI 응답만으로 실행하지 않습니다. 일반 파일의 이동·이름 변경까지 대화로 처리하는 기능은 아직 지원하지 않습니다. **실제 Codex와 새 도구 흐름의 종단 검증은 남아 있습니다.**

### 앱 관리·파일 열기

`앱 관리`는 전체 드라이브 검사 없이 앱을 조회합니다. Mac에서는 전용 제거기를 우선 사용하도록 안내하고, 일반 앱 본체만 별도 확인 후 휴지통으로 옮깁니다. 관련 데이터는 정확한 앱 식별자에 연결된 캐시·환경설정만 추가로 선택·검토하며 사용자 문서, Application Support, Containers, 공유 데이터는 자동 후보에서 제외합니다. Windows는 정식 `설치된 앱` 제거 화면으로 연결하고 앱 폴더·레지스트리·AppData를 추측 삭제하지 않습니다. 제거 화면을 열었다고 제거가 완료된 것은 아닙니다.

공간 정리 결과의 `열기`는 일반 문서·미디어를 기본 앱으로, 일반 폴더를 파일 탐색기로 엽니다. 프로그램·스크립트·앱 패키지는 실행하지 않고 위치만 표시합니다. `위치 표시`와 앱 안의 `하위 폴더 탐색`은 별도 행동입니다. 새 기능은 내장 AI/CLI/MCP의 제거 권한을 확대하지 않습니다.

### macOS 메뉴 막대

현재 소스에는 Swift 버전의 메뉴 막대 상주 흐름을 Rust로 추가했습니다. 창을 닫으면 앱은 숨겨지고, 메뉴 막대 아이콘에서 메모리·CPU·시스템 디스크와 실제 버전을 확인하거나 같은 창을 다시 열 수 있습니다. 아이콘 옆 메모리 사용률은 패널 또는 `설정 > 메뉴 막대`에서 표시·숨김을 전환하며 선택을 저장합니다. 숫자를 숨겨도 아이콘은 남습니다. 완전히 종료하려면 패널의 `종료` 또는 `⌘Q`를 사용하세요.

패널은 별도 WebView 없이 macOS 네이티브 UI를 사용하며, 파일·앱 목록 대신 집계 수치만 10초마다 읽습니다. 숨겨진 메인 창의 상태와 기존 메모리는 유지되므로 창을 닫는 것이 메모리 해제를 뜻하지는 않습니다. Windows 트레이 동작은 변경하지 않았습니다.

### 로컬 처리·토큰·전송 범위

파일 검색·검사·집계·후보 관리는 내 컴퓨터에서 처리하고, AI에는 판단에 필요한 제한된 요약을 전달하는 구조입니다. 로컬 파일 작업 자체는 LLM 토큰을 사용하지 않습니다. 절약의 핵심은 Rust라는 언어가 아니라 전체 파일 목록 대신 필요한 요약을 보내는 것입니다. 잘 구성된 일반 CLI도 비슷한 효율을 낼 수 있으며, 동일 작업 기준 토큰 절감률은 아직 측정하지 않았습니다.

클라우드 AI를 사용하면 이름·크기·개수·후보 번호와 질문·대화 기록은 공급자에게 전달됩니다. 앱의 폴더 요약과 새 후보 페이지에는 파일 본문과 전체 경로를 자동으로 넣지 않지만, 사용자가 직접 입력한 경로나 내용은 질문·기록에 포함될 수 있습니다. 로컬 CLI 실행이나 읽기 전용 권한은 완전한 오프라인 처리·외부 전송 차단을 뜻하지 않습니다. 별도 허용한 MCP 파일·문서 검색은 경로와 일치 문맥을 제공할 수 있습니다. 따라서 “파일 정보가 외부로 전혀 나가지 않는다”거나 일정 비율의 토큰 절약을 보장하지 않습니다.

### 자원 보호 범위와 검증 한계

본체 작업 메모리 512 MiB, 시스템 여유 RAM 256 MiB 기준으로 무거운 작업을 협조적으로 중단합니다. PDF·Office 처리 도구는 Rust 할당 예산 128 MiB와 15초 제한을 사용합니다. 색인 실패 시 이전 완료 색인을 보존합니다. 이는 전체 앱·WebView·CLI의 OS 하드쿼터나 메모리 누수 해결 보장이 아닙니다. 창을 숨겨도 기존 작업 상태와 메모리는 유지됩니다.

- 로컬 자동 검사: Rust 273개와 프런트엔드 43개 통과, 선택적 실제 CLI 진단 1개 제외.
- 미검증: 새 Codex 대화형 도구 종단 흐름, 장시간 전체 프로세스 메모리 안정성, 실제 사용자 앱 삭제·휴지통 비우기.
- 메뉴 막대 설정 저장·재시작·완전 종료는 확인했지만 아이콘 직접 클릭, 팝오버 내부 버튼·키보드 조작의 시각 검증은 남아 있습니다.
- 앱 전체 용량·설치 날짜·이름/날짜/용량 정렬 선택은 아직 제공하지 않습니다. 앱 목록의 포함 단어 검색은 지원합니다.
- Windows 설치 프로그램 빌드와 자동 검사는 CI에서 수행합니다. CI 통과가 실제 Windows 설치·GUI·휴지통 작업 검증을 뜻하지 않습니다.

## 안전과 클라우드 제외

스캔은 파일을 바꾸지 않습니다. 큰 파일·중복 검사, 드라이브 집계, 트리맵, 파일 카탈로그, 문서 색인은 알려진 클라우드 동기화 경로와 온라인 전용 항목을 제외합니다. macOS의 `~/Library/CloudStorage`, `~/Library/Mobile Documents`와 알려진 Google Drive·iCloud·OneDrive·Dropbox 경로를 순회 전에 차단하며, 인식된 클라우드 폴더를 직접 선택해도 검사하지 않습니다. 내려받아 둔 파일도 인식된 클라우드 루트 안에 있으면 제외됩니다. 임의 위치로 옮긴 동기화 폴더나 모든 공급자를 자동 식별한다고 보장하지는 않습니다.

중복은 크기 → 부분/전체 BLAKE3 → 바이트 비교로 검증합니다. 파일 이동은 선택·재검증·최종 확인·작업 기록을 거쳐 운영체제 휴지통으로 보냅니다. v1.7.0의 빈 폴더 이동은 별도 최종 확인이 필요합니다. 휴지통 비우기는 현재 사용자의 연결된 드라이브 휴지통 전체와 다른 앱의 항목도 포함하는 영구 삭제이며, 경고·체크박스·2분 유효 일회용 확인을 거칩니다. AI/CLI/MCP에는 제공하지 않습니다. 휴지통 이동 용량은 논리 크기이며 실제 여유 공간 증가와 같지 않습니다. 레지스트리 자동 삭제는 제공하지 않습니다.

메모리 정리는 시스템 전체 RAM·다른 앱·WebView 보조 프로세스·스왑·메모리 누수를 정리하지 않습니다. CPU 정리 기능은 없습니다. macOS의 일반 앱 정상 종료 요청은 별도 확인 동작이며 강제 종료하지 않습니다. Windows에서는 성능 조회만 제공하며 스왑은 페이지 파일 현재 사용량이 아닌 커밋 기반 추정치입니다.

Docker 관리는 기본적으로 꺼져 있습니다. 켠 경우에만 고정된 정리 명령을 사용하며, 볼륨은 제외하고 복구 불가 작업임을 따로 확인받습니다.

## AI·CLI·MCP

Codex 데스크톱 앱을 설치했다고 Codex CLI가 설치된 것은 아닙니다. 사용할 공급자의 CLI 설치·호환 버전·로그인 상태를 앱에서 확인하세요. 기존 요약 응답은 Mac에서 Codex로 검증했지만, v1.7.0의 새 빈 폴더 도구 종단 흐름은 아직 미검증입니다. Claude Code·Grok·Antigravity·Ollama 어댑터도 있지만 이번 Mac 릴리스에서 모두 실사용 검증한 것은 아닙니다.

앱 채팅은 항목 이름·크기 등이 담긴 제한된 폴더 요약과 질문·대화 이력을 선택한 공급자에 전달합니다. 로컬 CLI를 쓴다고 모델 처리까지 오프라인인 것은 아닙니다. MCP 정리 도구는 익명 후보 ID와 제한된 요약만 제공하며 승인·삭제 실행 도구는 없습니다. 파일·문서 검색을 별도로 허용하면 경로와 일치 문맥이 외부 클라이언트에 전달될 수 있습니다. 최종 파일 작업은 앱 안에서 확인합니다.

## 플랫폼과 개발

Rust stable, Node.js 22+, npm이 필요합니다. Windows는 WebView2와 MSVC Build Tools, macOS는 Xcode Command Line Tools가 필요합니다.

- `apps/desktop/`: 기본 Tauri/React 앱
- `crates/bloomsweepy-core/`: 공용 Rust 분석 엔진
- `crates/bloomsweepy-control/`, `apps/bloomsweepy-mcp/`: 로컬 제어 규격과 CLI/MCP 브리지
- `BroomSweepy/`: 레거시 SwiftUI 참고 구현

이번 기능은 Apple Silicon Mac 로컬 개발 빌드에서 구현과 일부 설치형 동작을 확인했습니다. 실제 검증 범위와 미검증 항목은 위 목록을 참고하세요. 최신 Windows 실행 검증은 별도이며 Windows 설치 파일은 Windows CI에서 빌드합니다. Mac 검증 빌드는 ad-hoc 서명이며 Apple 공증 완료를 의미하지 않습니다. 설치 파일과 플랫폼별 주의사항은 [릴리스](https://github.com/Dannykkh/bloomsweepy/releases)에서 확인하세요.

```sh
cd apps/desktop
npm ci
npm run tauri dev
```

```sh
# Repository root
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cd apps/desktop
npm run check
npm run test:all
npm run build
npm run tauri build
```

## 중요: 데이터 손실과 복구 책임

BroomSweepy는 사용자가 선택하고 최종 확인한 항목만 정리하도록 설계됐지만, 운영체제 권한·휴지통 설정·동기화 서비스·외장 또는 네트워크 드라이브 상태에 따라 파일 복원 가능성을 보장할 수 없습니다. Docker 정리는 운영체제 휴지통을 거치지 않으며 완료된 단계는 복구할 수 없습니다.

정리를 실행하기 전에 중요한 파일을 별도 저장장치나 신뢰할 수 있는 백업 서비스에 보관하고, 선택한 경로·파일·Docker 범주를 직접 확인해야 합니다. 사용자가 실행한 파일 이동·삭제·휴지통 비우기·Docker 정리로 발생한 데이터 손실이나 복구 실패에 대해 프로젝트 제공자와 기여자는 책임을 지지 않습니다. 다만 관련 법률상 배제할 수 없는 책임에는 해당 법률이 적용됩니다.
